# Feature Specification: Claude-Style UI Redesign

**Feature Branch**: `008-claude-ui-redesign`
**Created**: 2026-02-03
**Status**: Draft
**Input**: Редизайн интерфейса MITS в стиле нативного приложения Claude Desktop

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Минималистичный чат-интерфейс (Priority: P1)

Студент открывает MITS и видит чистый, современный интерфейс с центрированным чатом на тёмном фоне. Поле ввода находится внизу экрана, сообщения отображаются с аватарами пользователя и ассистента. Интерфейс выглядит профессионально и не отвлекает от обучения.

**Why this priority**: Основа пользовательского опыта — первое впечатление определяет желание продолжать использовать систему.

**Independent Test**: Открыть приложение и визуально оценить соответствие референсному дизайну Claude Desktop.

**Acceptance Scenarios**:

1. **Given** пользователь открывает MITS, **When** страница загружается, **Then** отображается тёмный фон с центрированным чатом (max-width 800px)
2. **Given** чат загружен, **When** пользователь смотрит на интерфейс, **Then** поле ввода закреплено внизу экрана
3. **Given** есть сообщения в чате, **When** пользователь просматривает историю, **Then** каждое сообщение имеет аватар (иконка для пользователя, иконка для ассистента)

---

### User Story 2 - Индикатор генерации ответа (Priority: P1)

Когда студент отправляет сообщение, он видит индикатор "печатает..." с анимацией, пока ассистент генерирует ответ. Это даёт понимание, что система работает.

**Why this priority**: Критически важно для UX — пользователь должен понимать, что происходит.

**Independent Test**: Отправить сообщение и наблюдать анимированный индикатор до появления ответа.

**Acceptance Scenarios**:

1. **Given** пользователь отправил сообщение, **When** начинается генерация, **Then** появляется анимированный индикатор "Думаю..."
2. **Given** индикатор отображается, **When** ответ готов, **Then** индикатор плавно заменяется текстом ответа
3. **Given** используется стриминг, **When** токены приходят, **Then** текст появляется постепенно с курсором в конце

---

### User Story 3 - Копирование блоков кода (Priority: P2)

Когда ассистент показывает код в ответе, студент может скопировать его одним нажатием кнопки, которая появляется при наведении на блок кода.

**Why this priority**: Важная функциональность для образовательного контента с примерами кода.

**Independent Test**: Получить ответ с кодом и скопировать его кнопкой.

**Acceptance Scenarios**:

1. **Given** в ответе есть блок кода, **When** пользователь наводит курсор, **Then** появляется кнопка копирования
2. **Given** кнопка копирования видна, **When** пользователь нажимает её, **Then** код копируется в буфер обмена
3. **Given** код скопирован, **When** копирование завершено, **Then** появляется подтверждение "Скопировано!"

---

### User Story 4 - Тёмная/Светлая тема (Priority: P2)

Студент может переключаться между тёмной и светлой темой в зависимости от предпочтений или времени суток.

**Why this priority**: Комфорт пользователя при длительной работе.

**Independent Test**: Переключить тему и убедиться, что все элементы корректно перекрашиваются.

**Acceptance Scenarios**:

1. **Given** приложение открыто, **When** пользователь открывает настройки, **Then** доступен переключатель темы
2. **Given** активна тёмная тема, **When** пользователь переключает на светлую, **Then** фон становится светлым, текст тёмным
3. **Given** тема изменена, **When** пользователь перезагружает страницу, **Then** выбранная тема сохраняется

---

### User Story 5 - Сворачиваемый sidebar (Priority: P3)

Студент может свернуть боковую панель с настройками, чтобы максимизировать пространство для чата.

**Why this priority**: Улучшает фокус на контенте, но не критично для базового функционала.

**Independent Test**: Нажать кнопку сворачивания и проверить, что sidebar скрывается.

**Acceptance Scenarios**:

1. **Given** sidebar развёрнут, **When** пользователь нажимает кнопку сворачивания, **Then** sidebar плавно скрывается
2. **Given** sidebar свёрнут, **When** пользователь нажимает кнопку разворачивания, **Then** sidebar плавно появляется
3. **Given** sidebar свёрнут, **When** экран узкий (мобильный), **Then** чат занимает всю ширину

---

### User Story 6 - Плавные анимации (Priority: P3)

Все переходы в интерфейсе имеют плавные анимации: появление сообщений, переключение тем, сворачивание элементов.

**Why this priority**: Полировка UX, не критично для функционала.

**Independent Test**: Выполнить любое действие и наблюдать плавность переходов.

**Acceptance Scenarios**:

1. **Given** новое сообщение появляется, **When** оно добавляется в чат, **Then** сообщение плавно выезжает снизу (200ms)
2. **Given** тема переключается, **When** применяются новые цвета, **Then** переход плавный (300ms fade)

---

### Edge Cases

- Что происходит при очень длинных сообщениях? Текст должен переноситься, не ломая layout.
- Как отображаются сообщения с LaTeX формулами? Формулы рендерятся корректно.
- Что если код в блоке очень длинный? Появляется горизонтальный скролл внутри блока.
- Как выглядит интерфейс на мобильных устройствах? Адаптивный дизайн, sidebar скрыт по умолчанию.

## Requirements *(mandatory)*

### Functional Requirements

**Layout & Structure**:
- **FR-001**: Система MUST отображать чат по центру экрана с максимальной шириной 800px
- **FR-002**: Система MUST закреплять поле ввода внизу экрана (sticky position)
- **FR-003**: Система MUST отображать аватары рядом с каждым сообщением (иконка пользователя, иконка ассистента)
- **FR-004**: Система MUST применять скруглённые углы (border-radius) к сообщениям и элементам ввода

**Темы & Стили**:
- **FR-005**: Система MUST поддерживать тёмную тему по умолчанию
- **FR-006**: Система MUST поддерживать светлую тему как альтернативу
- **FR-007**: Система MUST сохранять выбор темы между сессиями
- **FR-008**: Система MUST применять мягкие тени к сообщениям и элементам

**Интерактивность**:
- **FR-009**: Система MUST показывать анимированный индикатор при генерации ответа
- **FR-010**: Система MUST отображать кнопку копирования на блоках кода при наведении
- **FR-011**: Система MUST копировать код в буфер обмена при нажатии кнопки
- **FR-012**: Система MUST показывать подтверждение после копирования

**Sidebar**:
- **FR-013**: Система MUST позволять сворачивать/разворачивать sidebar
- **FR-014**: Система MUST сохранять состояние sidebar между сессиями
- **FR-015**: Sidebar MUST содержать настройки (тема, стриминг, инструменты)

**Анимации**:
- **FR-016**: Система MUST анимировать появление новых сообщений
- **FR-017**: Система MUST анимировать переключение тем
- **FR-018**: Система MUST анимировать сворачивание/разворачивание sidebar

**Адаптивность**:
- **FR-019**: Система MUST адаптироваться к мобильным экранам (width < 768px)
- **FR-020**: Система MUST скрывать sidebar по умолчанию на мобильных устройствах

### Key Entities

- **Message**: Сообщение в чате (роль: user/assistant, контент, временная метка)
- **Theme**: Тема оформления (dark/light, цветовая палитра)
- **UserPreferences**: Настройки пользователя (тема, sidebar state, streaming enabled)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% пользователей оценивают интерфейс как "современный" или "приятный" в опросе
- **SC-002**: Время загрузки интерфейса не превышает 2 секунд
- **SC-003**: Все анимации выполняются плавно (60fps) без заметных задержек
- **SC-004**: Интерфейс корректно отображается на экранах от 320px до 2560px
- **SC-005**: Копирование кода работает в 100% случаев на современных браузерах
- **SC-006**: Переключение темы занимает менее 300ms
- **SC-007**: Пользователи тратят на 20% меньше времени на навигацию по сравнению с текущим интерфейсом

## Assumptions

- Используется Gradio 4.x с поддержкой custom CSS и JavaScript
- Целевые браузеры: Chrome, Firefox, Safari, Edge (последние 2 версии)
- Основная целевая аудитория использует desktop, но мобильная поддержка важна
- Тёмная тема предпочтительнее, так как студенты часто работают вечером

## Out of Scope

- Полная кастомизация цветов пользователем
- Множественные темы (только dark/light)
- Офлайн-режим
- Push-уведомления
