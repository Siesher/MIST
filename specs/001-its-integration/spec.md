# Feature Specification: ITS Integration - Полная система интеллектуального репетитора

**Feature Branch**: `001-its-integration`
**Created**: 2026-01-30
**Status**: Draft
**Input**: User description: "Помоги мне создать систему, отталкиваясь от текущей итерации проекта, для реализации системы Intelligent Tutoring System"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Базовая сессия обучения математике (Priority: P1)

Студент запускает систему, выбирает раздел математики (алгебра, анализ, геометрия) и начинает решать задачу. Система анализирует его ответы, диагностирует ошибки и направляет к правильному решению через наводящие вопросы (сократический метод), никогда не давая прямых ответов.

**Why this priority**: Это ядро системы - основной пользовательский сценарий, демонстрирующий все ключевые возможности: многоагентную архитектуру, RAG-подсказки и сократический метод. Без этого сценария система не имеет ценности.

**Independent Test**: Запустить Gradio-интерфейс, выбрать задачу по алгебре, ввести неправильный ответ, убедиться что система задает наводящие вопросы без раскрытия ответа.

**Acceptance Scenarios**:

1. **Given** студент выбрал тему "линейные уравнения", **When** он вводит неверное решение "x = 5" для уравнения "2x + 3 = 7", **Then** система задает наводящий вопрос типа "Что получится, если подставить x = 5 в левую часть уравнения?"
2. **Given** студент сделал 3 неверные попытки, **When** он запрашивает помощь, **Then** система предоставляет прогрессивные подсказки (концептуальная → процедурная → конкретная) из базы знаний RAG
3. **Given** студент решил задачу правильно, **When** ответ проверяется, **Then** система обновляет модель знаний студента (Knowledge Tracing) и предлагает следующую задачу соответствующей сложности

---

### User Story 2 - Сессия программирования с выполнением кода (Priority: P2)

Студент выбирает алгоритмическую задачу, пишет код на Python, система выполняет код в защищенной песочнице, анализирует результаты и направляет к оптимальному решению через вопросы о логике и структуре алгоритма.

**Why this priority**: Программирование - вторая ключевая дисциплина после математики. Отличается от математики необходимостью выполнения кода и анализа его корректности.

**Independent Test**: Выбрать задачу на сортировку, ввести код с ошибкой, убедиться что система выполняет код, показывает результаты тестов и задает вопросы о логике ошибки.

**Acceptance Scenarios**:

1. **Given** студент выбрал задачу "Найти максимум в списке", **When** он отправляет код с ошибкой (например, `return min(arr)`), **Then** система запускает тесты, показывает провалившиеся случаи и спрашивает "Что делает функция min() и почему результат не соответствует ожидаемому?"
2. **Given** код студента прошел все тесты, **When** код неоптимален (O(n^2) вместо O(n)), **Then** система задает вопросы об эффективности: "Сколько раз выполняется внутренний цикл? Можно ли обойтись одним проходом?"
3. **Given** студент застрял на задаче, **When** он запрашивает подсказку, **Then** система предоставляет концептуальную помощь (паттерн решения), не показывая конкретный код

---

### User Story 3 - Диагностика и адаптивное обучение (Priority: P3)

Система автоматически определяет типичные заблуждения студента (misconceptions), отслеживает его прогресс через Knowledge Tracing и адаптирует сложность задач и стратегию обучения под индивидуальный профиль.

**Why this priority**: Персонализация - ключевое отличие ITS от обычных учебников. Требует работы всех агентов (Profiler, Planner) и накопленных данных о студенте.

**Independent Test**: Провести сессию из 10 задач, проверить что система корректно определяет паттерны ошибок и адаптирует сложность.

**Acceptance Scenarios**:

1. **Given** студент систематически ошибается в операциях с отрицательными числами, **When** Profiler анализирует историю ответов, **Then** система классифицирует ошибку как MISCONCEPTION и предлагает задачи для устранения этого заблуждения
2. **Given** показатель знания навыка (BKT probability) выше 0.85, **When** студент выбирает следующую задачу, **Then** система предлагает задачи повышенной сложности или переход к следующему навыку в графе зависимостей
3. **Given** студент демонстрирует низкую уверенность (ConfidenceLevel.LOW), **When** Planner выбирает стратегию, **Then** выбирается стратегия ENCOURAGEMENT с поддерживающим тоном

---

### User Story 4 - Мультидисциплинарная поддержка STEM (Priority: P4)

Система поддерживает все 5 целевых дисциплин (математика, программирование, физика, химия, биология) с единым интерфейсом и специализированными базами знаний для каждой области.

**Why this priority**: Расширение на все STEM дисциплины - стратегическая цель, но требует значительной базы знаний. Математика и программирование достаточны для MVP.

**Independent Test**: Переключиться между дисциплинами, решить по одной задаче в каждой, проверить релевантность подсказок.

**Acceptance Scenarios**:

1. **Given** студент выбрал дисциплину "Физика", **When** он решает задачу по кинематике, **Then** система использует подсказки из `data/knowledge/hints/physics.jsonl` и применяет соответствующую терминологию
2. **Given** студент переключается между дисциплинами, **When** он возвращается к математике, **Then** система сохраняет его профиль знаний для каждой дисциплины отдельно

---

### Edge Cases

- Что происходит при отсутствии соединения с Ollama API?
- Как система обрабатывает пустой или невалидный ввод студента?
- Что если код студента выполняется дольше таймаута (30 секунд)?
- Как система реагирует на попытки получить прямой ответ ("просто скажи ответ")?
- Что если база знаний не содержит подсказок для конкретной темы?
- Как обрабатывается превышение лимита VRAM при длинных диалогах?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять веб-интерфейс (Gradio) для взаимодействия студента с репетитором
- **FR-002**: Система MUST направлять все ответы через 4-агентный pipeline: Profiler → Planner → Tutor → Verifier
- **FR-003**: Verifier MUST блокировать ответы, содержащие прямое решение задачи (answer leak detection)
- **FR-004**: Система MUST использовать RAG для обогащения ответов релевантными подсказками и информацией о типичных ошибках
- **FR-005**: Система MUST выполнять код Python в изолированной песочнице с таймаутом и ограничениями безопасности
- **FR-006**: Система MUST отслеживать состояние знаний студента через Bayesian Knowledge Tracing (BKT)
- **FR-007**: Profiler MUST классифицировать ошибки по типам: CONCEPTUAL, PROCEDURAL, CARELESS, NOTATION, INCOMPLETE, MISCONCEPTION
- **FR-008**: Planner MUST выбирать стратегию обучения из 7 доступных на основе профиля студента
- **FR-009**: Система MUST сохранять сессии и историю диалогов для аналитики
- **FR-010**: Система MUST работать в пределах 6GB VRAM (RTX 2080 constraint)
- **FR-011**: Система MUST поддерживать как минимум 2 дисциплины (математика, программирование) с полной функциональностью
- **FR-012**: Система MUST предоставлять прогрессивные подсказки (3 уровня: концептуальный, процедурный, конкретный)
- **FR-013**: Система MUST логировать метрики качества (Telling@10, Success@10, Hint Efficiency)

### Key Entities

- **Student Session**: Активная сессия обучения; содержит ID студента, выбранную дисциплину, историю диалогов, текущую задачу, состояние Knowledge Tracing
- **Task/Problem**: Учебная задача; содержит условие, правильный ответ, тему, сложность, связанные навыки в графе
- **Student Profile**: Профиль знаний студента; содержит уровни освоения навыков (BKT probabilities), историю ошибок, предпочтения обучения
- **Hint**: Подсказка из базы знаний; содержит текст, тему, уровень (conceptual/procedural/specific), связанные misconceptions
- **Misconception**: Типичное заблуждение; содержит описание, паттерны распознавания, корректирующую стратегию
- **Agent Response**: Ответ агента; содержит текст, стратегию, обоснование, метаданные проверки качества

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Студенты решают задачи успешно (Success@10 > 60%) - более 60% задач решаются в пределах 10 обменов сообщениями
- **SC-002**: Система не раскрывает ответы (Telling@10 < 15%) - менее 15% сессий заканчиваются прямым раскрытием ответа
- **SC-003**: Подсказки эффективны (Hint Efficiency < 2.5) - в среднем требуется менее 2.5 подсказок для успешного решения
- **SC-004**: Система отвечает быстро - время генерации ответа менее 5 секунд для 95% запросов
- **SC-005**: Knowledge Tracing точен (AUC-ROC > 0.75) - модель корректно предсказывает успех студента на следующей задаче
- **SC-006**: Система стабильна - работает без ошибок и перезапусков в течение 8-часовой сессии
- **SC-007**: Код студентов выполняется безопасно - 100% потенциально опасных операций блокируются песочницей
- **SC-008**: Студенты завершают обучающие сессии - более 70% начатых сессий доводятся до логического завершения (решение задачи или осознанный выход)

## Assumptions

- Ollama установлен и доступен локально на порту 11434
- Модель Qwen3-8B (или совместимая) загружена в Ollama
- Cerebras API ключ доступен для генерации обучающих данных (фаза fine-tuning)
- Целевая машина имеет RTX 2080 или совместимую GPU с минимум 8GB VRAM
- Python 3.11+ установлен с необходимыми зависимостями из requirements.txt
- Существующие компоненты (агенты, RAG, база знаний) работоспособны и протестированы
