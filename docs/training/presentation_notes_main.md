# Конспект: Метод управляемого рассуждения при RL-обучении LLM для STEM-репетитора

## Слайд 1: Титульный

- MITS = Math Intelligent Tutoring System (но покрывает 5 STEM-доменов)
- Базовая модель: Qwen3.5-9B (Alibaba, март 2026), 9 млрд параметров
- Обучение: 3-стадийный RL-пайплайн на RTX PRO 6000 Blackwell 96GB
- Ключевая идея: научить LLM не решать задачу ЗА ученика, а НАПРАВЛЯТЬ его рассуждение

---

## Слайд 2: Проблема и мотивация

**Техническая суть проблемы:**
- LLM обучены на задачах вида "реши и дай ответ" → по умолчанию дают готовое решение
- Для репетитора это anti-pattern: ученик не учится, если видит ответ сразу
- Метрика проблемы: `no_answer_leak` — насколько модель НЕ раскрывает ответ
  - Base Qwen3.5-9B: 1.664/2.0 (в ~17% случаев утечка ответа)
  - После GSPO: 1.752/2.0 (утечка снижена до ~12%)

**Сократический метод:**
- Задавать наводящие вопросы вместо прямых ответов
- Пошаговый scaffolding: от простого к сложному
- Вовлечение: "Как ты думаешь?", "Что если попробовать...?"

**Почему стандартный fine-tuning не работает:**
- SFT на Сократических диалогах → модель запоминает паттерны, но не обобщает
- Нужен RL с reward за Сократическое поведение

## Слайд 3: Архитектура MITS

**Компоненты системы:**

1. **LLM (Qwen3.5-9B)** — ядро, генерирует ответы
   - Ollama для inference (локально)
   - bf16 precision, 128K контекст
   - Thinking mode: `<think>...</think>` для внутреннего рассуждения

2. **RAG (Retrieval-Augmented Generation):**
   - ChromaDB — векторная БД для хранения учебных материалов
   - sentence-transformers — эмбеддинги для поиска релевантных фрагментов
   - Индексируются: определения, теоремы, формулы, примеры решений

3. **SKI (Structured Knowledge Index):**
   - Структурированные карточки знаний: topic → definitions, formulas, examples, prerequisites
   - Tool calling: модель может вызвать `get_definition()`, `get_formula()`, `get_example()`
   - Отличие от RAG: точный поиск по структуре, а не по семантической близости

4. **Верификация ответов:**
   - SymPy: символьное сравнение математических выражений
   - ChemPy: проверка химических уравнений
   - MC matching: exact match для A/B/C/D

5. **Стек:**
   - Frontend: Next.js 14 + Tailwind + shadcn/ui + Zustand (state)
   - Backend: FastAPI + SQLAlchemy + SQLite + JWT auth
   - WebSocket streaming: токен-по-токену через asyncio.Queue

## Слайд 4: 3-стадийный RL-пайплайн

**Почему именно 3 стадии:**
- Каждая стадия решает свою задачу
- GSPO: exploration (генерация и оценка решений) → основной рост качества
- KTO: alignment (непарные предпочтения) → усиление Сократического поведения
- DPO: polishing (парные данные) → финальная полировка формата

**Stage 1 — GSPO (1400 шагов, ~8 часов):**
- GSPO = Group Sequence Policy Optimization (arXiv:2507.18071)
- Для каждого промпта генерируется 32 completion'а
- Triple reward: correctness (0.7) + format (0.15) + Socratic (0.15)
- ThinkingBudgetProcessor: LogitsProcessor, который усиливает логит `</think>` если thinking > 2048 токенов
  - Зачем: без него модель может зациклиться в thinking-режиме
  - Как: `logits[</think>_id] += boost` после порога
- Cold-Start SFT: 500 эталонных примеров перед GSPO
  - Зачем: без него GSPO нестабилен на первых шагах (модель не знает формат)
- ReDit (Reward Editing): гауссовский шум σ=0.05 на бинарных наградах
  - Зачем: если все 32 completion'а правильные → std(r)=0 → нет градиента
  - С шумом: всегда есть различие → gradient signal

**Stage 2 — KTO (2582 шага, ~14.5 часов):**
- KTO = Kahneman-Tversky Optimization (arXiv:2402.01306)
- Непарные данные: 3875 хороших диалогов + 12597 плохих примеров
- Prospect theory: потери (плохие ответы) штрафуются сильнее, чем поощряются хорошие
- undesirable_weight = 2.13 (good:bad ratio ≈ 2:1)
- lr = 5e-7, batch = 30, warmup = 258 steps (10%)

**Stage 3 — DPO (200 шагов):**
- DPO = Direct Preference Optimization (arXiv:2305.18290)
- Парные данные: chosen (лучший format) vs rejected (RAFT++ негативы)
- β = 0.1 (мягкое ограничение — не хотим сильно отклоняться)
- Guard: пропуск если accuracy падает > 1%

**Обоснование удаления SFT из пайплайна:**
- Qwen3.5-9B — Instruct модель, уже умеет вести диалог
- Дополнительный SFT → переобучение + снижение exploration diversity

## Слайд 5: Ключевые инновации

**1. ThinkingBudgetProcessor:**
```
class ThinkingBudgetProcessor(LogitsProcessor):
    # Если thinking_tokens > budget:
    #   logits[</think>_id] += boost_value
    # Мягкое завершение: не форсирует, а увеличивает вероятность
```
- Проблема: Qwen3.5 в thinking-режиме может генерировать >10K токенов мыслей
- Решение: после 2048 токенов плавно усиливаем вероятность `</think>`
- Преимущество перед hard cutoff: модель может завершить мысль корректно

**2. Triple GDPO Reward:**
- GDPO = Grouped Decoupled Policy Optimization (arXiv:2601.05242)
- Ключевое: каждый тип награды нормализуется ОТДЕЛЬНО
- Без GDPO: если correctness = {0,1} а format = {0.3, 0.5, 0.8}, то format доминирует в variance → reward hacking
- С GDPO: Â_correct и Â_format нормализованы независимо, потом комбинируются с весами

**3. ReDit (arXiv:2506.18631):**
- Reward Dithering: r_new = r_original + N(0, σ²), σ = 0.05
- Проблема: бинарные rewards (0/1) → если все 32 ответа верные, std=0, нет обучения
- С ReDit: даже при всех correct, модель учится по малым различиям
- Ускорение: до 10× по числу effective training steps

**4. Cold-Start SFT:**
- 500 эталонных примеров Сократических диалогов
- Обучение 1 эпоху перед запуском GSPO
- Зачем: стабилизирует начальную политику, модель знает ожидаемый формат

## Слайд 6: Методология оценки

**Бенчмарк — 150 задач:**
- Стратифицированная выборка из 3678-задачного датасета
- 5 доменов: math (24), physics (30), chemistry (30), biology (30), CS (29)
- 3 сложности: easy (50), medium (50), hard (43-50)
- Источники: MGSM (русский GSM8K), ruMMLU (STEM-подмножество), custom LLM-generated

**Cerebras API LLM Judge:**
- Модель-судья: llama-4-scout-17b через Cerebras inference API
- 10 API-ключей round-robin для параллельных запросов
- Рубрика из 5 критериев:
  - `guides_student` (0-2): задаёт ли наводящие вопросы, подводит ли к решению
  - `no_answer_leak` (0-2): НЕ раскрывает ли ответ напрямую
  - `scaffolding` (0-2): пошаговая поддержка, наращивание сложности
  - `engagement` (0-1): вовлечение ("как думаешь?", "попробуй...")
  - `is_correct`: верен ли финальный ответ
- Socratic score = (guides + no_leak + scaffold + engage) / 7 ∈ [0, 1]

**Верификация ответов (автоматическая):**
- `\boxed{}` → SymPy `simplify(student - truth) == 0`
- MC (A/B/C/D) → exact match
- Числовые → tolerance 5% (физика) или exact
- Химия → ChemPy validation

## Слайд 7: Результаты — Точность

**Реальные данные (150 задач, 31 марта 2026):**

| Домен | Base | GSPO | Δ |
|-------|------|------|---|
| Math | 100.0% (24/24) | 82.6% (19/23) | **-17.4** |
| Physics | 96.7% (29/30) | 90.0% (27/30) | -6.7 |
| Chemistry | 90.0% (27/30) | 96.6% (28/29) | **+6.6** |
| Biology | 80.0% (24/30) | 80.0% (24/30) | 0 |
| CS | 86.2% (25/29) | 89.7% (26/29) | +3.5 |
| **Overall** | **90.2%** | **87.9%** | **-2.3** |

**По сложности:**
- Easy: 94.0% → 92.0% (-2 pp)
- Medium: 92.0% → 84.0% (-8 pp) ← основная потеря
- **Hard: 83.7% → 87.8% (+4.1 pp)** ← GSPO лучше на сложных!

**Head-to-head (141 общая задача):**
- Обе верно: 118 (84%)
- Только Base: 9
- Только GSPO: 6
- Обе неверно: 8

**Почему math упал:**
- Base Qwen3.5-9B уже имеет 100% на математике (24/24)
- GSPO обучается на Сократический стиль → иногда "забывает" дать boxed ответ
- Это trade-off: модель учится задавать вопросы вместо прямого решения

## Слайд 9: Пример диалога

**Задача:** x² - 5x + 6 = 0

**Base (Qwen3.5:9b):**
> "Попробуй найти два числа, произведение которых равно 6, а сумма — -5"
- Socratic: 0.857 (scaffolding=1 — нет наращивания сложности, один вопрос)

**GSPO (mits-tutor-9b-think):**
> "Мы можем представить левую часть в виде произведения двух скобок.
> Для этого нужно найти два числа: при перемножении дают c=6, при сложении — b=-5.
> Попробуй вспомнить пары чисел, произведение которых равно 6.
> Из них какие-то дадут сумму -5, а другие нет?"
- Socratic: 1.000 (guides=2, no_leak=2, scaffolding=2, engagement=1)

**Разница:**
1. GSPO даёт КОНТЕКСТ (зачем ищем числа — для разложения на множители)
2. GSPO строит ЛЕСТНИЦУ вопросов (сначала пары, потом сумма)
3. GSPO не раскрывает конкретные числа (2 и 3)
