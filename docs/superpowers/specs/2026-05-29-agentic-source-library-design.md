# Design: Агентная библиотека источников (без RAG)

**Дата:** 2026-05-29
**Статус:** approved (механизм v2 — агентный list/read/grep + граф)
**Ветка:** 019-ns-vstar-dpo

## Проблема и принцип

Пользователь хочет: загружать несколько источников на вкладке (включая файлы
PDF/изображения/URL), и чтобы **агенты сами решали, как и когда их использовать**
— реально улучшая и ответы, и генерацию заданий.

**Жёсткое ограничение:** НЕ RAG. Embedding-retrieval (chunk → вектор → top-k)
считается устаревшим/тупиковым. Механизм — **агентный**, как агент работает с
кодовой базой: `list` / `read` / `grep`. Нулевые эмбеддинги в живом пути.

`DocumentRetriever` (etap-1/2, embedding-RAG) снимается с живого пути и остаётся
**измеренным baseline'ом** для диплома (абляция closed/open-book 2/8→6/8): «мы
сравнили embedding-RAG и выбрали агентные инструменты».

## Компоненты

### 1. `src/tools/source_tools.py` — инструменты-«библиотекарь»

По образцу `navigator_tools` (модульные DEFINITIONS + FUNCTIONS + инжектор
состояния). Все функции синхронные над загруженной в память библиотекой; БД и
любые тяжёлые операции — на стороне сервиса до tool-loop.

| Инструмент | Назначение |
|---|---|
| `list_sources()` | `[{id, title, domain, kind, chars}]` — что вообще есть в библиотеке |
| `read_source(source_id, part=1)` | срез ~9000 симв. + «часть X/N» — агент читает док по частям (влезает в 64K ctx) |
| `search_in_source(query, source_id=None)` | лексический grep: подстрока + окружающий контекст; по одному источнику или по всем |

`set_source_library(library: dict[str, dict])` — инжектор: сервис кладёт
`{id: {title, domain, kind, text}}` перед tool-loop. Никаких эмбеддингов.

**Контракт:** что делает — даёт агенту читать/искать в загруженных источниках;
как использовать — `list` → выбрать → `read`/`search`; зависит — только от
инъецированной in-memory библиотеки.

### 2. Проводка в `orchestrator_service`

- `_load_source_library(db) -> dict` (async) — грузит `SourceTable(status=extracted)`
  в `{id:{title,domain,kind,text}}` (кап на размер/кол-во для бюджета).
- Перед tool-loop: `set_source_library(lib)`; регистрируем `SOURCE_TOOL_DEFINITIONS`
  в **chat + guided + task_generator**.
- **task_generator → агентный:** добавить режим в блок инструментов и в `use_tools`.
- **Убрать пассивную инъекцию etap-2** (метод `_retrieve_source_chunks`,
  вычисление `source_chunks`, инъекции в guided/chat). `TutoringContext.chunks`
  как поле оставляем (безвредно, покрыто тестом).
- Системные промпты (chat/guided/task_generator): подсказка «есть библиотека
  источников — list/read/search; опирайся на них для ответов и задач».

### 3. Граф (Knowledge Forge) — без изменений

Источники по-прежнему извлекаются в граф (`_run_extraction`); Navigator-инструменты
уже дают агенту структурное знание. Агент имеет ОБА не-RAG канала: сырые доки
(read/grep) и граф (концепты/связи).

### 4. Vision при загрузке файлов

`/ingest/image` и PDF-без-текстового-слоя → OCR через `mits-vision`
(llama-swap, `enable_thinking=false`, рендер страниц PyMuPDF). PDF с текстовым
слоем → `fitz.get_text()` напрямую.

### 5. Фронтенд — загрузка файлов на вкладке

`AddSourceModal`: переключатель **текст / файл / URL**. Файл → `/ingest/{pdf,image}`
(multipart) → текст → `/sources`; URL → `/ingest/url` → текст → `/sources`.
Хелперы в `api.ts`.

## Поток данных

```
вкладка: файл/URL/текст ──/ingest──> текст ──/sources──> SourceTable(extracted)
                                                              │ (фон: граф)
чат/задача: вопрос ─> агент ─tool─> list_sources / read_source / search_in_source
                              └─tool─> explore_concept / find_learning_path (граф)
                       агент сам решает, что и когда вызвать → ответ/задача
```

## Обработка ошибок

- Нет источников → `list_sources` возвращает пустой список; агент отвечает как обычно.
- `read_source` с неверным id / part вне диапазона → понятная JSON-ошибка.
- Vision/ingest сбой → сообщение в модалке; источник не создаётся.
- Tool-loop устойчив (как уже есть для SKI/Navigator): сбой инструмента → JSON-ошибка в петлю.

## Тестирование

- Юнит `tests/test_source_tools.py`: list/read/grep над внедрённой библиотекой
  (детерминированно, без БД/LLM): пагинация read, grep находит подстроку с
  контекстом, пустая библиотека, неверный id.
- Живая абляция: генерация задания и ответ **с инструментами vs без** на ВКР
  Фирсова — задача/ответ опираются на конкретику источника только с инструментами.

## Вне scope

- Удаление `DocumentRetriever`/etap-2 (оставляем как baseline-артефакт).
- Per-user/сессионная изоляция источников (сейчас глобальны).
- Семантический (embedding) поиск — намеренно НЕ делаем.
