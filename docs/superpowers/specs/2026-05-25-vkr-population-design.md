## Контекст и проблема

Каркас ВКР готов (`docs/diploma/ВКР_Сухацкий_2026.docx` — титул/структура/40 источников/placeholder'ы).
Цель — **полный черновик всех глав** (80-100 стр) с ГОСТ-оформлением, включая **формулы через LaTeX**
(настоящие Word OMML, не текст).

Объём слишком велик для одного spec → **декомпозиция на 6 под-проектов** (главы), каждый — свой цикл
написания. Этот spec фиксирует **общую архитектуру наполнения** + scope **первого цикла**
(assembler-инфраструктура + извлечение готовых источников).

**Готовый контент (~27 стр):** `НИР_controlled_reasoning.docx` → Главы 1.3-1.4 + 3.5-3.8 + 4.x;
`Курсовой_проект.docx` → 1.1 + 2.3-2.4.

## Goals

1. `scripts/assemble_vkr.py` — собирает ВКР из skeleton + markdown-глав, с OMML-формулами
2. Контент глав в `docs/diploma/chapters/{section_id}.md` (редактируемый, git-friendly)
3. Извлечь НИР/Курсовой → стартовые `chapters/*.md` (pandoc docx→md)
4. Идемпотентная пересборка `ВКР_Сухацкий_2026.docx`

## Non-goals

- Написание всех 6 глав в первом цикле (последующие циклы)
- Ручной рендер формул (pandoc делает LaTeX→OMML)
- Изображения/скриншоты (вставляются вручную в Word позже; в md — маркеры)

## Архитектура (pandoc-гибрид) — проверена end-to-end

**Pipeline:**
1. python-docx строит каркас (reuse `build_vkr_skeleton`: титул, структура, библиография)
2. Для секции с `chapters/{section_id}.md`:
   - pandoc `{id}.md --reference-doc=ВКР(10) (3).docx -o temp_fragment.docx` → стили образца + OMML
   - python-docx: `deepcopy` body-элементов фрагмента (кроме `sectPr`) → вставить после заголовка секции
3. Нет .md → текущий placeholder

**Проверено тестом:** inline `$..$` + display `$$..$$` → 5 OMML; markdown-таблица → docx table;
параграфы получают стиль `Normal` образца; merge через deepcopy сохраняет OMML и таблицы.

**pandoc:** `C:\Users\Maksim\AppData\Local\Pandoc\pandoc.exe` (НЕ в PATH git bash — локатор в скрипте:
проверить PATH → fallback `%LOCALAPPDATA%\Pandoc\pandoc.exe`).

**Section-id mapping:** 4-е поле в `STRUCTURE` (None для глав-контейнеров):
- `00_introduction` → ВВЕДЕНИЕ
- `01-1_its`, `01-3_llm`, `01-4_rl` … → 1.1, 1.3, 1.4
- `02-3_multiagent`, `02-4_kt` → 2.3, 2.4
- `03-5_gspo` … `03-8_vstar` → 3.5-3.8
- `04-2_baseline`, `04-3_per_stage`, `04-7_vstar` → 4.x
- `99_conclusion` → ЗАКЛЮЧЕНИЕ

## Источники (извлечение)

- pandoc `docx→md`: `НИР_controlled_reasoning.docx` → markdown (формулы → LaTeX, таблицы → md-таблицы),
  затем нарезка по заголовкам в `chapters/*.md` соответствующих секций.
- Аналогично Курсовой → секции навигации.
- Извлечённый md — **стартовая точка**, правится под структуру ВКР (не дословный перенос).

## Verification (первый цикл)

- `assemble_vkr.py` запускается, пересобирает `ВКР_Сухацкий_2026.docx`
- Секции с извлечённым контентом содержат текст (не placeholder)
- OMML-формулы присутствуют (re-open, `m:oMath` count > 0)
- Стили заголовков/Normal соответствуют образцу
- `verify_vkr_skeleton.py` всё ещё PASS (структура цела)
- Идемпотентность: повторный запуск даёт тот же результат

## Open questions / риски

- **Table count в merge-тесте показал 4** (ожидалось ~2) — исследовать при реализации (возможно
  skeleton/pandoc создают вложенные/доп. таблицы). Не блокер.
- **pandoc docx→md качество**: сложные таблицы/формулы НИР могут потребовать ручной правки извлечённого md.
- **latex2mathml не нужен** (pandoc покрывает) — путь отвергнут в пользу pandoc.
- **Формулы**: pandoc покрывает основной LaTeX; экзотические окружения проверить на реальном НИР-контенте.
