Третья стадия пайплайна применяет Direct Preference Optimization (DPO) [3] для финальной полировки формата и стиля ответов. Если KTO выравнивает педагогическую стратегию (переключение с прямых ответов на наводящие вопросы), то DPO решает более тонкую задачу: устраняет остаточные нарушения форматирования, стабилизирует длину ответа и закрепляет правила использования LaTeX-разметки.

## Теория DPO

DPO [3] устанавливает прямую алгебраическую связь между парами предпочтений и обновлением параметров языковой модели, минуя промежуточное обучение reward-модели. Метод показывает, что оптимальная политика при RLHF с Bradley-Terry моделью предпочтений допускает замкнутое решение в форме смещённой референсной модели. Функция потерь DPO имеет вид:

$$\mathcal{L}_{\text{DPO}}(\pi_\theta, \pi_{\text{ref}}) = -\mathbb{E}_{(x,\, y^+,\, y^-) \sim \mathcal{D}}\Bigl[
\log \sigma\!\Bigl(
\beta \log \frac{\pi_\theta(y^+ \mid x)}{\pi_{\text{ref}}(y^+ \mid x)} -
\beta \log \frac{\pi_\theta(y^- \mid x)}{\pi_{\text{ref}}(y^- \mid x)}
\Bigr)
\Bigr],$$

где $y^+$ — предпочтительный (chosen) ответ, $y^-$ — нежелательный (rejected), $\pi_{\text{ref}}$ — замороженная референсная модель (чекпойнт после KTO), $\beta = 0{,}1$ — параметр, регулирующий близость к референсной политике.

В отличие от PPO [26], DPO не требует онлайн-генерации и score-функции, что значительно сокращает вычислительные затраты. В отличие от KTO, DPO работает с явными парами `(chosen, rejected)` для одного и того же промпта, что делает его более точным для финальной коррекции конкретных паттернов поведения.

## Датасет для DPO

Обучающие пары формируются из контрастных выходов KTO-модели. Процедура отбора:

1. Для каждого промпта из `preference_pairs.jsonl` генерируется два ответа KTO-моделью с разными параметрами семплирования (temperature 0,7 и 1,2).
2. Пара (ответ при $T=0{,}7$, ответ при $T=1{,}2$) оценивается по трём автоматическим критериям: соответствие LaTeX-форматированию, длина ответа (оптимально 2–4 предложения), наличие завершающего вопроса.
3. Ответ с бо́льшей суммарной оценкой выбирается как `chosen`, с меньшей — как `rejected`.

Итоговый датасет содержит пары из 3875 диалогов `dialogs.jsonl`. Фокус намеренно смещён на формат, а не на педагогическое содержание: содержательное выравнивание уже выполнено на стадии KTO.

## Гиперпараметры стадии

| Параметр | Значение |
|---|---|
| Библиотека | TRL `DPOTrainer` |
| LoRA rank $r$ | 16 |
| LoRA $\alpha$ | 32 |
| Скорость обучения | $5 \cdot 10^{-7}$ |
| $\beta$ | $0{,}1$ |
| Batch size | 2 |
| Количество эпох | 1 |
| Оптимизатор | AdamW |
| Чекпойнт | `Siesher/mits-qwen3-9b-final` |

Один эпох достаточен, так как задача DPO на этой стадии ограничена: устранить небольшое число специфических паттернов (избыточная длина, пропуск LaTeX, отсутствие вопроса в конце), не переписывая поведение, сформированное на стадиях GSPO и KTO. Более длительное обучение привело бы к нежелательному переобучению и потере вариативности ответов.

## Результат стадии

Стадия DPO обеспечила прирост предметной точности на 1,7 п.п. (с 64,8% до 66,5%) при суммарном росте относительно базовой модели +11,4 п.п. Качественно: доля ответов с сократическими вопросами возросла с 61% до 68%, средний Socratic score — с 0,58 до 0,64. Средняя длина thinking-блока сократилась с 590 до 510 токенов — модель стала рассуждать более компактно и целенаправленно, что снижает латентность inference при деплое. Чекпойнт стадии `Siesher/mits-qwen3-9b-final` служит начальной точкой для четвёртой стадии — V-STaR-DPO.
