Интерфейс пользователя я реализовал в виде одностраничного приложения (Single-Page Application, SPA) на фреймворке Next.js 14 с использованием механизма App Router. Next.js 14 я выбрал из-за поддержки React Server Components (RSC), позволяющих рендерить компоненты на стороне сервера без передачи лишнего JavaScript клиенту, и встроенной поддержки WebSocket-соединений через клиентские компоненты (подробное сравнение с альтернативами — Приложение Е.4).

## Структура приложения

Приложение организовано согласно соглашению App Router: каждый маршрут представлен файлом `page.tsx` в соответствующей директории. Итоговая структура включает пять основных страниц:

| Маршрут | Компонент | Назначение |
|---|---|---|
| `/` | `app/page.tsx` | Главная страница, список активных сессий |
| `/auth/login` | `app/auth/login/page.tsx` | Страница входа |
| `/auth/register` | `app/auth/register/page.tsx` | Регистрация пользователя |
| `/chat/[sessionId]` | `app/chat/[sessionId]/page.tsx` | Чат-интерфейс сократического тьютора |
| `/dashboard` | `app/dashboard/page.tsx` | Аналитика: успеваемость, граф навыков |

Корневой layout (`app/layout.tsx`) оборачивает приложение в `AuthProvider` и `ThemeProvider`, реализуя глобальный контекст аутентификации и тематического оформления. Навигация реализована через компонент `Sidebar` (раздел `components/layout/`), отображающий список сессий, иконки разделов и статус подключения.

Визуальная часть построена на библиотеке компонентов shadcn/ui, основанной на Radix UI с оформлением Tailwind CSS. Используются компоненты `Card`, `Button`, `Input`, `ScrollArea`, `Dialog`, `Avatar`, а также кастомные компоненты `ModeSelector` (выбор режима диалога), `ThinkingPanel` (отображение блока рассуждений модели) и `ChatInput` (поле ввода с поддержкой загрузки изображений).

## Управление состоянием: Zustand Store

Глобальное состояние чата управляется через библиотеку Zustand — минималистичное хранилище состояния без шаблонного кода Redux. Хранилище `chatStore.ts` содержит:

- `messages: Message[]` — массив сообщений текущей сессии;
- `isStreaming: boolean` — флаг активного стрима;
- `thinkingContent: string` — накапливаемый буфер thinking-рассуждений;
- `sessionId: string | null` — идентификатор активной сессии;
- `mode: 'chat' | 'guided_learning' | 'task_generator'` — режим взаимодействия;
- `knowledgeState: KnowledgeStateData | null` — данные об освоении навыков для визуализации.

Хранилище реализует принцип иммутабельности: все мутации производятся через функции-селекторы (`addMessage`, `appendToken`, `setThinking`, `setStreaming`), что исключает прямую мутацию состояния и упрощает отладку.

## Hooks: useChat и useWebSocket

Логика WebSocket-стриминга инкапсулирована в два пользовательских хука.

Хук `useWebSocket` управляет жизненным циклом WebSocket-соединения: установку соединения с адресом `ws://backend/ws/{sessionId}?token={jwt}`, обработку входящих сообщений, автоматическое переподключение при разрыве и закрытие соединения при демонтаже компонента. Хук возвращает функцию `sendMessage(content: string)` для отправки пользовательских сообщений.

Хук `useChat` является высокоуровневым фасадом над `useWebSocket`. Он:
1. Диспетчеризирует входящие WebSocket-события по типам (`token`, `thinking_token`, `message_complete`, `error`, `knowledge_state`);
2. Вызывает соответствующие мутации Zustand Store (`appendToken`, `setThinking`);
3. Управляет флагом `isStreaming` для блокировки повторных отправок;
4. Сохраняет завершённое сообщение в локальное состояние после получения события `message_complete`.

Разделение ответственности между двумя хуками соответствует принципу единственной ответственности: `useWebSocket` обрабатывает транспортный уровень, `useChat` — бизнес-логику отображения.

## Рендеринг математических формул

Для отображения LaTeX-формул в чате используется библиотека KaTeX — быстрый рендерер математических выражений, работающий полностью на стороне клиента без внешних зависимостей. Компонент `MathRenderer.tsx` парсит содержимое сообщения регулярным выражением, разделяя текст, инлайн-формулы (`$...$`) и блочные формулы (`$$...$$`), после чего рендерит каждый фрагмент соответствующим способом: текстовые фрагменты — через React.Fragment, формульные — через `katex.renderToString()` с последующей установкой через `dangerouslySetInnerHTML`.

Компонент `SmartContent` дополнительно обрабатывает блоки Mermaid (диаграммы) и Plotly (интерактивные графики), передавая их в соответствующие компоненты `MermaidBlock` и `PlotlyBlock`. Это позволяет тьютору отображать не только текст с формулами, но и структурированные визуализации — например, графики функций или диаграммы химических реакций.

## Режимы работы интерфейса

Компонент `ModeSelector` предоставляет выбор из трёх режимов взаимодействия, каждый из которых определяет серверный маршрут обработки запроса:

- **chat** — прямой диалог с LLM без агентного пайплайна; используется для свободных вопросов;
- **guided_learning** — полный мультиагентный пайплайн (Profiler → Planner → Tutor → Verifier);
- **task_generator** — генерация учебных задач по заданной теме и уровню сложности.

Выбранный режим сохраняется в Zustand Store и передаётся в теле WebSocket-сообщения. Серверный оркестратор маршрутизирует запрос в соответствии с полученным режимом через конфигурацию `MODE_CONFIGS`.
