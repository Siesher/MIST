## Состав бенчмарка

Для экспериментальной оценки разработан комплексный бенчмарк из **3 678 задач** по пяти STEM-дисциплинам. Задачи сформированы из трёх источников: MGSM Russian (математические задачи школьного уровня, перевод на русский язык) [39] — **250 задач**, ruMMLU STEM (русскоязычный срез MMLU по STEM-дисциплинам) [38] — **3 210 задач**, авторский набор (задачи, адаптированные для русскоязычных учеников 7–11 классов с акцентом на сократический стиль) — **218 задач**.

Распределение задач по доменам представлено в таблице 4.1.

| Домен | Источники | Задач | Доля |
|---|---|---|---|
| Математика | MGSM + ruMMLU + авторский | 1 200 | 32,6% |
| Физика | ruMMLU + авторский | 800 | 21,8% |
| Химия | ruMMLU + авторский | 678 | 18,4% |
| Биология | ruMMLU + авторский | 400 | 10,9% |
| Информатика | ruMMLU + авторский | 600 | 16,3% |
| **Итого** | — | **3 678** | **100%** |

В пределах каждого домена задачи распределены по трём уровням сложности: лёгкий (easy), средний (medium) и сложный (hard). Сложность определялась на основе уровня образовательной программы: лёгкие задачи соответствуют 7–8 классу, средние — 9–10 классу, сложные — 11 классу и олимпиадному уровню. Такое распределение важно для оценки эффективности curriculum learning (от простого к сложному), применяемого на стадии GSPO (в разделе 3.5).

## Метрики оценки

Основная метрика — **accuracy** (доля корректных ответов). Итоговая метрика по всему бенчмарку вычисляется как macro-average по 5 доменам:

$$\text{Accuracy}_{\text{macro}} = \frac{1}{5}\sum_{d=1}^{5} \text{Accuracy}_d$$

Такой подход даёт каждому домену равный вес независимо от числа задач в нём, что исключает доминирование математики (1 200 задач) над биологией (400 задач) при агрегировании.

Дополнительно отслеживаются:

- **answer extraction rate** — доля completions, из которых удалось извлечь ответ (контролирует качество форматирования);
- **truncation rate** (доля отсечённых completions) — процент генераций, прерванных по достижению лимита длины без завершения thinking-блока; до применения ThinkingBudgetProcessor [34] составлял **100%**, после — **14,3%** (подробнее в разделе 4.4).

## Верификация ответов

Проверка правильности ответов автоматизирована и дифференцирована по домену:

- **Математика** — библиотека SymPy с символьным упрощением. Позволяет корректно сопоставлять эквивалентные алгебраические выражения: например, $x^2 + 2x + 1$ и $(x+1)^2$ признаются одинаковыми без буквального совпадения строк.
- **Химия** — библиотека ChemPy. Поддерживается проверка балансировки уравнений реакций и стехиометрических расчётов.
- **Физика** — регулярные выражения (regex) с числовым допуском для единиц измерения; принимаются варианты «9,8 м/с²» и «9.8 m/s²» как эквивалентные.
- **Биология и информатика** — exact match (точное совпадение после нормализации регистра и пробелов). Для задач по программированию дополнительно выполняется запуск кода и сравнение вывода.

Таким образом, верификация не требует ручной разметки и полностью автоматизирована, что исключает человеческий фактор при оценке большого числа completions. Инструмент верификации реализован в скрипте `training/scripts/evaluate_stage.py`.

## Условия проведения экспериментов

Все эксперименты по оценке производились в идентичных условиях для обеспечения воспроизводимости:

- **Модель для деплоя**: GGUF Q4_K_M (4-битное квантование, Mixed) через Ollama. Квантование выбрано как баланс между качеством (потери точности относительно bf16 не превышают 0,5–1,0 п.п.) и требованиями к памяти (≈6 ГБ VRAM против 18 ГБ для bf16).
- **Температура**: $T = 0{,}3$ — умеренно детерминированная генерация; при $T = 0$ наблюдается нечувствительность к альтернативным формулировкам, при $T > 0{,}5$ — чрезмерный разброс.
- **Максимальная длина**: 4 096 токенов на completion (включая thinking-блок).
- **Инфраструктура**: локальный llama-server на порту 8081 с KV-кэшированием (turbo3 stack), `--parallel 3`.
- **Бенчмарк зафиксирован**: 0% пересечения между eval-набором и обучающими данными, что верифицировано сравнением хэшей задач.

Обучение проводилось на GPU NVIDIA A100 80 ГБ (среда Google Colab / Lightning AI) в формате bf16 без квантования. Для дообучения использовались библиотеки Unsloth, TRL (GRPOTrainer / KTOTrainer / DPOTrainer) и PEFT с LoRA (в разделе 3.5).

## Протокол оценки по стадиям

Каждая стадия пайплайна `Qwen3.5-9B → GSPO → KTO → DPO → V-STaR-DPO` оценивалась независимо: чекпойнт конвертировался в GGUF Q4_K_M, загружался в Ollama и прогонялся через полный бенчмарк в 3 678 задач. Результаты фиксировались в отчёте per-domain accuracy, answer extraction rate и truncation rate. Такой протокол позволяет изолировать вклад каждой стадии и исключить интерференцию между экспериментами.
