## Мотивация Dual Knowledge Tracing

Классическая байесовская трассировка знаний (Bayesian Knowledge Tracing, BKT) [5] моделирует освоение каждого навыка как двухсостояниевую скрытую марковскую цепь и обеспечивает хорошую интерпретируемость, однако не учитывает зависимости между навыками и историческую динамику в долгосрочном горизонте. Глубокая трассировка знаний (Deep Knowledge Tracing, DKT) [6] решает проблему межнавыковых зависимостей с помощью рекуррентной нейронной сети, но страдает от недостаточной интерпретируемости и нестабильности при малом числе взаимодействий.

В системе MITS применяется **Dual Knowledge Tracing** — гибридная модель, объединяющая преимущества обоих подходов. Вероятностный компонент (BKT) обеспечивает устойчивость при cold-start (малое число ответов), нейросетевой компонент (DKT) улавливает долгосрочные паттерны и межнавыковые корреляции. Комбинированная оценка mastery по навыку $k$ в момент времени $t$:

$$
\text{mastery}_{k,t} = 0{,}4 \cdot \text{BKT}_{k,t} + 0{,}5 \cdot \text{DKT}_{k,t} + 0{,}1 \cdot \text{recency}_{k,t}
$$

Весовые коэффициенты 0,4 / 0,5 / 0,1 выбраны эмпирически: доминирование DKT оправдано его более высокой предсказательной точностью на длительных сессиях; вес BKT обеспечивает интерпретируемость начальных оценок; recency-компонент штрафует за большой промежуток с момента последней успешной демонстрации навыка.

## BKT-компонент

### Модель

BKT моделирует состояние знания ученика $L_{k,t}$ — латентную вероятность владения навыком $k$ в момент $t$. Стандартная параметризация включает четыре параметра [5]:

- $p_0$ — начальная вероятность знания навыка;
- $p_T$ (transit) — вероятность освоения навыка за один ход при незнании;
- $p_S$ (slip) — вероятность ошибки при знании навыка;
- $p_G$ (guess) — вероятность правильного ответа при незнании.

Обновление апостериорной вероятности знания после наблюдения ответа $a_t \in \{0, 1\}$ (неверно/верно):

$$
P(L_{k,t} \mid a_t) = \frac{P(a_t \mid L_{k,t}) \cdot P(L_{k,t})}{P(a_t)}
$$

Для правильного ответа ($a_t = 1$):

$$
P(L_{k,t} \mid a_t=1) = \frac{P(L_{k,t}) \cdot (1 - p_S)}{P(L_{k,t}) \cdot (1 - p_S) + (1 - P(L_{k,t})) \cdot p_G}
$$

Переход к следующему моменту (с учётом возможного освоения):

$$
P(L_{k,t+1}) = P(L_{k,t} \mid a_t) + (1 - P(L_{k,t} \mid a_t)) \cdot p_T
$$

### Параметры по умолчанию

В системе используются параметры, усреднённые по базе Carnegie Learning [17]: $p_0 = 0{,}3$, $p_T = 0{,}15$, $p_S = 0{,}1$, $p_G = 0{,}25$ для большинства навыков. Для высокосложных концептов (olympiad) параметры скорректированы: $p_T = 0{,}05$ (медленное освоение). Параметры хранятся в таблице `skill_params` SQLite и могут быть обновлены через байесовскую оптимизацию по накопленным данным пользователей.

## DKT-компонент

### Архитектура

DKT [6] использует рекуррентную нейронную сеть (LSTM) для предсказания вероятности правильного ответа на следующий вопрос по навыку $k_{t+1}$ на основе истории взаимодействий. Вход сети: бинарный вектор $(k_t, a_t)$, закодированный как one-hot по паре «навык–результат». Скрытое состояние $\mathbf{h}_t$ суммирует всю историю сессии. Выход: вектор вероятностей $\hat{y}_t \in \mathbb{R}^{|K|}$, где $|K|$ — число навыков в графе.

В текущей реализации DKT запускается как лёгкая LSTM (1 слой, hidden\_dim=64) поверх истории сессии. Обновление происходит инкрементально при каждом новом ответе, что обеспечивает константную latency (~5 мс) независимо от длины сессии.

В Lite-профиле (CPU 16 ГБ) DKT отключён флагом `enable_dkt=False` в ресурсном профиле; компонента $0{,}5 \cdot \text{DKT}$ перераспределяется на BKT: $\text{mastery} = 0{,}9 \cdot \text{BKT} + 0{,}1 \cdot \text{recency}$.

## Recency-компонент

Компонента `recency` учитывает кривую забывания Эббингауза: навык, не практиковавшийся длительное время, должен получать сниженный mastery-балл. Реализована через экспоненциальное убывание:

$$
\text{recency}_{k,t} = \exp\!\left(-\frac{\Delta t_{k}}{14 \cdot 24 \cdot 3600}\right)
$$

где $\Delta t_{k}$ — время (в секундах) с момента последнего успешного ответа по навыку $k$; период полураспада принят равным 14 суткам. Таким образом, навык, не использовавшийся две недели, получает `recency = 0,5`, что снижает общий mastery на $0{,}1 \cdot 0{,}5 = 0{,}05$ — достаточно для инициирования стратегии `review`.

## Граф навыков (Knowledge Forge)

### Структура графа

Knowledge Forge реализует гетерогенный граф знаний, расширяющий плоский skill-граф 6 типами узлов и 10 типами рёбер.

**Типы узлов**: `concept` (понятие), `formula` (формула), `theorem` (теорема), `example` (задача-пример), `method` (метод решения), `misconception` (типичное заблуждение).

**Типы рёбер**:

| Тип ребра | Семантика | Использование |
|-----------|-----------|---------------|
| `prerequisite` | A обязательно для B | Построение траектории |
| `part_of` | A является частью B | Иерархия концептов |
| `generalizes` | A обобщает B | Расширение знаний |
| `confused_with` | A часто путают с B | Детекция misconceptions |
| `common_error_for` | A — типичная ошибка для B | ToM re-ranking |
| `applies_to` | Метод A применим к задаче B | RAG-поиск |
| `derived_from` | A выводится из B | Theorem proving |
| `proves` | A доказывает B | Верификация |
| `best_taught_after` | A эффективнее учить после B | Soft ordering |
| `illustrates` | A иллюстрирует B | Выбор примеров |

### Состав графа

Граф включает **40+ компетенций** по пяти доменам. Миграция из плоского skill-графа выполнена скриптом `scripts/migrate_to_forge.py`: 51 концепт + 57 рёбер типа `prerequisite` перенесены в Knowledge Forge; дополнительно добавлены узлы типов `formula`, `example`, `misconception` и рёбра `confused_with`, `common_error_for`.

Пример фрагмента графа по математике (функции и производные):

```
[functions_basics] --prerequisite--> [limits_intuition]
[limits_intuition] --prerequisite--> [derivatives_basic]
[derivatives_basic] --prerequisite--> [chain_rule]
[chain_rule] --confused_with--> [product_rule]
[product_rule] --common_error_for--> [sign_error_misconception]
[derivatives_basic] --illustrates--> [velocity_example]
```

### Персонализированная навигация

`PersonalizedNavigator` объединяет граф знаний с динамической mastery-моделью ученика. При запросе диагностики пробела вызывается метод `diagnose_gap(student_id, failed_concept_id, belief_state)`:

1. Рекурсивно обходятся prerequisite-предшественники концепта.
2. Для каждого предшественника проверяется mastery < threshold (0,7).
3. При наличии `BeliefState` с `confidence ≥ 0,5` применяется ToM-aware re-ranking: концепты, соответствующие `active_misconception`, поднимаются в приоритете.
4. Возвращается `GapDiagnosis` с `root_gap` — глубинным пробелом, требующим первоочерёдного внимания.

Метод `find_learning_frontier` определяет множество концептов, непосредственно достижимых с учётом текущего mastery: концепт входит во frontier, если все его prerequisite освоены на уровне ≥ 0,6.

### Эволюция графа

Knowledge Forge поддерживает **самоэволюцию** от тьюторских сессий через агентов `SessionAnalyzer` и `GraphEvolver`. По завершении сессии SessionAnalyzer анализирует трассу диалога и генерирует предложения типа `{NEW_NODE, NEW_EDGE, MISCONCEPTION, REORDER}`. GraphEvolver применяет двухуровневую верификацию (rule-based → LLM) и при превышении порога уверенности $\theta$ фиксирует изменения в JSON-файл. Транзакционная семантика гарантирует целостность графа при прерывании записи.

### Производительность

Граф персистируется в JSON-файле (~100 КБ для 83 узлов), что обеспечивает: загрузку при старте < 50 мс; выполнение операций навигации (`find_path`, `diagnose_gap`) < 20 мс; полное соответствие требованию latency TTFT ≤ 3 с, поскольку Knowledge Forge не является узким местом конвейера.
