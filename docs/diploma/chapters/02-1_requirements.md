## Функциональные требования

Проектирование системы начинается с формализации требований, вытекающих из анализа предметной области (глава 1) и педагогических принципов сократического диалога [1, 8, 16]. Требования разбиты на функциональные (описывают поведение системы) и нефункциональные (описывают качественные характеристики).

### Предметная область и уровни сложности

Система должна охватывать **пять STEM-доменов**: математику, физику, химию, биологию и информатику — в соответствии с программой 7–11 классов общеобразовательной школы. Для каждого домена формируется собственная база задач и граф навыков; метрики оценки адаптированы к специфике дисциплины (SymPy для математики и физики, ChemPy для химии, exact match для биологии и информатики).

Адаптивность системы обеспечивается поддержкой **четырёх уровней сложности**: elementary (базовые определения и формулы), intermediate (применение в знакомом контексте), advanced (перенос знаний в новый контекст) и olympiad (нестандартные задачи, требующие синтеза нескольких концепций). Уровень сложности текущей задачи определяется модулем Knowledge Tracing (раздел 2.4) на основе актуального mastery-профиля ученика и принципа зоны ближайшего развития (ZPD, [16]).

### Режимы работы

Система реализует три режима взаимодействия пользователя с системой.

**Режим сократического диалога** (guided_learning) является основным. В данном режиме активируется полный конвейер мультиагентной обработки (Profiler → Planner → Tutor → Verifier), система удерживается от прямых ответов и направляет ученика к самостоятельному выводу через наводящие вопросы. Критерий педагогической пригодности ответа (no-spoiler) проверяется верификатором; доля ответов с сократическими вопросами достигает 61% после KTO-выравнивания (против 34% у базовой модели).

**Режим прямого чата** (chat) предназначен для свободного общения с языковой моделью без педагогических ограничений. В данном режиме агентный конвейер не активируется; запрос передаётся непосредственно в LLMClient и результат транслируется через WebSocket-стриминг.

**Режим генерации задач** (task_generator) обеспечивает создание новых учебных заданий по заданному навыку и уровню сложности. Генерация реализована на базе модели LLMClient.generate() с шаблонным промптом; задачи сохраняются в базе данных и могут быть использованы в последующих сессиях guided_learning.

## Нефункциональные требования

### Производительность и latency

Ключевым нефункциональным требованием является задержка до первого токена (time-to-first-token, TTFT) не более **3 секунд** при работе на локальном оборудовании пользователя. Данный порог обоснован исследованиями в области взаимодействия человека с компьютером: задержка свыше 3 с разрушает восприятие диалога как непрерывного [9]. Требование достигается за счёт GGUF-квантизации модели (Q4_K_M через Ollama) и оптимизированного KV-кеша (TurboQuant turbo3, --parallel 3).

Полная генерация ответа не нормируется жёстко, поскольку стриминг обеспечивает прогрессивное отображение токенов. При параметрах деплоя (llama-server, C:/OpenCode, port 8081) скорость составляет ~12 токенов/с на Lite-профиле (CPU 16 ГБ RAM) и ~35 токенов/с на Standard-профиле (GPU 6 ГБ VRAM).

### Языковые требования

Система полностью локализована для **русскоязычных учеников**. Языковая модель Qwen3.5-9B выбрана в том числе за высокое качество генерации на русском языке [2]. Интерфейс фронтенда, системные промпты агентов, база задач и граф навыков — все компоненты разработаны на русском языке. Математические и химические символы передаются в LaTeX-нотации, которую KaTeX рендерит на стороне клиента.

### Локальный деплой

Система спроектирована для работы **без облачных зависимостей**: все компоненты (модель, база данных, векторное хранилище) запускаются локально. Минимальные системные требования: 16 ГБ RAM, процессор с поддержкой AVX2 (Lite-профиль). Деплой модели через Ollama обеспечивает унифицированный API, совместимый с OpenAI-форматом, что упрощает замену модели без изменения кода агентов.

Дополнительные нефункциональные требования:

| № | Требование | Значение |
|---|------------|----------|
| НФ-1 | Надёжность API | 99% успешных запросов при нормальной нагрузке |
| НФ-2 | Безопасность | JWT-авторизация всех endpoints; SQLite с файловыми правами ОС |
| НФ-3 | Расширяемость | Добавление нового домена не требует изменений ядра агентов |
| НФ-4 | Тестируемость | 85%+ покрытие кода модульными тестами |
| НФ-5 | Портируемость | Запуск на Windows 11, Ubuntu 22+, macOS 13+ без изменений |

## Пользовательские сценарии (Use Cases)

### UC-1: Решение задачи с сократическим сопровождением

**Актор**: ученик (7–11 класс). **Предусловие**: пользователь авторизован, выбрана дисциплина.

1. Пользователь вводит условие задачи или запрашивает задачу по теме.
2. Система (Profiler) анализирует запрос, определяет тему и текущий mastery по навыкам из Knowledge Tracing.
3. MentalModelAgent строит BeliefState: активное заблуждение, предсказанные реакции, уровень уверенности.
4. Planner выбирает стратегию обучения (scaffolding / guided_discovery / error_correction) и формирует план.
5. Tutor (LLM, Qwen3.5-9B) генерирует ответ с наводящим вопросом; токены транслируются через WebSocket.
6. Ученик отвечает; цикл повторяется до достижения правильного решения.
7. Verifier оценивает финальный ответ (SymPy/ChemPy/regex); mastery обновляется через BKT+DKT.

**Постусловие**: mastery по затронутым навыкам обновлён; сессия сохранена в БД.

### UC-2: Просмотр учебной траектории

**Актор**: ученик. **Предусловие**: зарегистрирован и прошёл не менее одной сессии.

1. Пользователь открывает страницу аналитики.
2. Система отображает граф навыков с цветовой индикацией mastery (зелёный — освоено, жёлтый — в процессе, серый — не начато).
3. PathSlime генерирует k=2..5 альтернативных путей к выбранной цели.
4. Пользователь выбирает предпочтительный стиль траектории (quick / gradual / example_rich).

### UC-3: Генерация задания по теме

**Актор**: ученик или преподаватель.

1. Пользователь задаёт тему и уровень сложности.
2. TaskGen (режим task_generator) генерирует задачу с условием, правильным ответом и ключевыми шагами решения.
3. Задача сохраняется в базе и может быть использована в guided_learning сессии.
