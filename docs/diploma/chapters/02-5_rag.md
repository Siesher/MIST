## Назначение RAG-подсистемы

Дообученная языковая модель Qwen3.5-9B обладает обширными внутренними знаниями по STEM-дисциплинам, однако не имеет доступа к специфическим педагогическим ресурсам: конкретным задачам из базы данных, разобранным решениям с пошаговыми комментариями и каталогу типичных заблуждений учеников. Метод дополненной генерации с извлечением (Retrieval-Augmented Generation, RAG) позволяет динамически обогащать контекст тьютора актуальной и верифицированной информацией из внешних источников без повторного обучения модели.

## Архитектура RAG

RAG-подсистема построена на паре **ChromaDB** + **sentence-transformers** и функционирует следующим образом.

**Индексация** (offline): документы из всех источников разбиваются на фрагменты (chunks), каждый кодируется моделью sentence-transformers в плотный вектор (dense embedding) и сохраняется в коллекцию ChromaDB вместе с метаданными (домен, тип документа, сложность, идентификатор задачи).

**Поиск** (online, при каждом ходе диалога): запрос — тема текущего хода и описание пробела от `GapDiagnosis` — кодируется той же моделью; выполняется поиск $k$ ближайших соседей ($k = 5$) по косинусному расстоянию; возвращённые фрагменты включаются в контекст тьютора.

Модель эмбеддингов: **`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`** — многоязычная модель, демонстрирующая высокое качество семантического поиска на русском языке при малом размере (118 МБ) и быстром инференсе (~5 мс на CPU). Альтернативы с более высоким качеством (E5-large, BGE-M3) требуют GPU и существенно увеличивают latency.

## Источники контекста

### База задач

Основной источник — коллекция задач по пяти доменам, организованная по навыкам и уровням сложности. В ChromaDB каждая задача индексируется с полями: `task_id`, `domain`, `skill_id`, `difficulty` (elementary/intermediate/advanced/olympiad), `text` (условие), `answer` (правильный ответ), `solution_steps` (список шагов решения).

При генерации ответа тьютора RAG извлекает задачи, **аналогичные текущей**, но с известными разборами: это позволяет тьютору строить наводящие вопросы, опираясь на конкретные примеры, а не на общие соображения.

Размер базы на момент разработки: более 3678 задач, перекрывающих все пять доменов (включая задачи бенчмарка: MGSM Russian 250 + ruMMLU STEM 3210 + авторский набор 218).

### База разобранных решений (worked examples)

Worked examples — пошаговые разборы типовых задач с педагогическими комментариями — формируют отдельную ChromaDB-коллекцию. Каждый разбор содержит: условие, шаги решения с объяснением «почему», типичные ошибки на каждом шаге, ключевые вопросы для самопроверки.

Worked examples используются тьютором двумя способами:
1. **Аналогия**: тьютор предлагает ученику рассмотреть похожий, но более простой пример.
2. **Scaffolding**: при `mastery < 0,3` тьютор может указать на соответствующий шаг разбора без раскрытия ответа текущей задачи.

### База заблуждений (misconceptions)

Каталог типичных ошибок учеников по каждому навыку: 8 классов misconceptions (sign_error, operation_confusion, variable_misuse, incorrect_formula, domain_confusion, unit_error, scope_error, notation_confusion), каждый с примерами ошибочных рассуждений и шаблонами вопросов для исправления.

MentalModelAgent использует базу заблуждений при классификации `active_misconception`. При обнаружении заблуждения RAG дополнительно извлекает шаблоны «исправляющих вопросов» — наводящих вопросов, специфичных для данного класса ошибки, — которые Planner включает в `LearningPlan.hints`.

## Структура ChromaDB-коллекций

| Коллекция | Записей | Размерность эмбеддинга | Метаданные фильтрации |
|-----------|---------|------------------------|------------------------|
| `tasks` | 3678+ | 384 (MiniLM-L12) | domain, skill_id, difficulty |
| `worked_examples` | 800+ | 384 | domain, skill_id |
| `misconceptions` | 200+ | 384 | domain, misconception_class |

ChromaDB хранит все коллекции в директории `data/chromadb/` в виде DuckDB-файла, что обеспечивает персистентность без внешнего сервера и совместимость с локальным деплоем.

## Интеграция в конвейер

RAG-поиск выполняется между Planner и Tutor: после формирования `LearningPlan` оркестратор вызывает `RAGService.get_context(topic, skill_id, misconception, k=5)`. Функция выполняет три параллельных поиска (по задачам, worked examples, misconceptions), объединяет результаты и возвращает объект `RAGContext` с полями `hints`, `worked_examples`, `misconception_fixes`.

Суммарная latency RAG-поиска при CPU inference: ~20–40 мс для трёх параллельных запросов к ChromaDB, что не является узким местом конвейера.

## Фильтрация по метаданным

ChromaDB поддерживает фильтрацию результатов по метаданным до семантического поиска (pre-filtering). Это критично для педагогической корректности: тьютор не должен предлагать примеры из другого домена или уровня сложности, недоступного ученику. Фильтр формируется на основе `StudentProfile.domain` и `LearningPlan.scaffolding_level`:

```python
results = collection.query(
    query_embeddings=[query_embedding],
    n_results=5,
    where={"domain": profile.domain, "difficulty": {"$lte": max_difficulty}}
)
```
