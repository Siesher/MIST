# ВВЕДЕНИЕ

В последние годы наблюдается стремительное развитие и повсеместное внедрение больших языковых моделей (Large Language Models, LLM). Особое место среди них занимают модели с режимом рассуждения (thinking mode или reasoning mode), такие как DeepSeek-R1 \[1\], Qwen3.5 \[2\] и QwQ. Эти модели способны генерировать промежуточные цепочки рассуждений (chain-of-thought, CoT) в специальных тегах \`\<think\>\...\</think\>\` перед формулировкой окончательного ответа, что существенно повышает качество решения задач, требующих многошагового логического вывода.

Для STEM-дисциплин (наука, технологии, инженерия, математика) способность к рассуждению имеет критическое значение, поскольку решение задач этих областей требует последовательности математических преобразований, физических выкладок, химических расчётов и программного кода. Применение таких моделей в образовательном контексте --- в качестве интеллектуальных систем обучения (Intelligent Tutoring Systems, ITS) --- предъявляет дополнительные требования: модель должна не только решать задачи корректно, но и объяснять ход решения ученику, следуя сократическому методу обучения \[4\].

Для достижения этих требований необходимо домен-специфичное дообучение базовой модели с использованием обучения с подкреплением (RL). Алгоритм Group Relative Policy Optimization (GRPO) \[5\] и его усовершенствованная версия GSPO (Group Sequence Policy Optimization) \[2\] являются современными методами RL-обучения для LLM, использующими относительные преимущества внутри группы completions для оценки качества ответов без необходимости отдельной value-network.

Однако при применении GRPO/GSPO к моделям с thinking mode возникает критическая проблема: во время rollout-генерации модель может войти в неограниченный цикл рассуждений и не сгенерировать закрывающий токен \`\</think\>\` в пределах бюджета максимальной длины последовательности. Данная проблема документирована в открытых источниках (vLLM issue #15418, open-r1) и приводит к тому, что 100 % сгенерированных completions обрезаются по максимальной длине, не содержат финального ответа и получают нулевую награду. В таких условиях алгоритм GRPO не может вычислить значимые преимущества (advantages), градиент равен нулю, и обучение не сходится.

Актуальность данного исследования обусловлена практической необходимостью обучения домен-специфичных thinking-моделей для STEM-образования при отсутствии в открытых источниках готовых методов решения описанной проблемы. Имеющиеся публикации (DeepSeek-R1, DAPO, Dr. GRPO, S-GRPO, Tina, ReDit, DuP-PO, HAPO) рассматривают отдельные аспекты улучшения GRPO, но не предлагают целостной методологии обеспечения сходимости обучения thinking-моделей.

Целью настоящей работы является разработка и апробация метода управляемого рассуждения, обеспечивающего сходимость GRPO/GSPO-обучения языковых моделей с thinking mode и позволяющего получить компактную STEM-специализированную тьюторскую модель на основе Qwen3.5-9B.

Для достижения поставленной цели сформулированы задачи:

1.  Провести анализ существующих методов RL-обучения языковых моделей (GRPO, GSPO, Dr. GRPO, KTO, DPO) и идентифицировать корневую причину несходимости thinking-режима.

2.  Разработать компонент ThinkingBudgetProcessor --- процессор логитов, обеспечивающий гарантированное завершение фазы рассуждения в пределах заданного бюджета токенов.

3.  Предложить стратегию Cold-Start SFT, обеспечивающую ненулевую базовую точность для последующего RL-обучения.

4.  Интегрировать ReDit-дитеринг наград для преодоления проблемы нулевой дисперсии преимуществ при разреженной награде.

5.  Построить трёхстадийный пайплайн GSPO → KTO → DPO и провести эксперименты на бенчмарке из 3 678 STEM-задач.

6.  Сравнить полученные результаты с базовой моделью и альтернативными подходами; подготовить научную публикацию.

Научная новизна работы заключается в следующем:

7.  Идентифицирована корневая причина несходимости GRPO-обучения thinking-моделей --- отсутствие механизма принудительного завершения фазы рассуждения в TRL-генерации.

8.  Предложен компонент ThinkingBudgetProcessor в виде LogitsProcessor с двухступенчатым механизмом «soft nudge + hard force», обеспечивающий завершение thinking при сохранении качества решений.

9.  Предложена комбинация ThinkingBudgetProcessor + Cold-Start SFT + ReDit-дитеринг как целостная методология, устраняющая три ключевых барьера сходимости GSPO-обучения.

Практическая значимость работы состоит в получении специализированной STEM-модели Qwen3.5-9B, превосходящей базовую версию на 11,4 процентных пункта на бенчмарке из 3 678 задач по 5 дисциплинам, с наибольшим приростом в биологии (+14,4 п.п.) и информатике (+12,1 п.п.), пригодной для интеграции в интеллектуальную тьюторскую систему для русскоязычных учеников 7--11 классов.

# 1. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ ИССЛЕДОВАНИЯ

## 1.1. Механизмы рассуждения в языковых моделях

Chain-of-Thought (CoT) prompting, предложенный Wei et al. в 2022 году \[3\], стал прорывным техническим приёмом, существенно повысившим качество решения LLM математических, логических и символических задач. Суть метода состоит в том, что модель пошагово генерирует промежуточные рассуждения перед формулировкой окончательного ответа. Это позволяет декомпозировать сложные задачи на более простые подзадачи и использовать расширенный контекст для окончательного принятия решения.

Первоначальный подход CoT был prompt-based: специальные инструкции в системном промпте побуждали модель генерировать рассуждения. С появлением моделей семейства DeepSeek-R1 \[1\], QwQ и Qwen3.5 \[2\] возник новый класс моделей --- thinking-модели, в которых механизм рассуждения интегрирован архитектурно через специальные токены-делимитеры \`\<think\>\` и \`\</think\>\`. В зависимости от значения параметра \`enable_thinking\` в chat template модель может либо включать thinking-блок (расширенное рассуждение), либо сразу формулировать ответ.

Thinking-модели демонстрируют значительное превосходство над своими non-thinking аналогами на задачах, требующих многоступенчатого вывода. DeepSeek-R1, например, достигает результатов, сопоставимых с OpenAI o1, на математических бенчмарках AIME и MATH. Однако при дообучении таких моделей для конкретных доменов возникают новые технические вызовы, не характерные для non-thinking моделей.

## 1.2. Обучение с подкреплением на основе групповой политики (GRPO)

Group Relative Policy Optimization (GRPO) \[5\] --- современный алгоритм RL-обучения языковых моделей, представленный компанией DeepSeek в работе DeepSeekMath. В отличие от PPO, GRPO не требует отдельной value-network (critic): для каждого prompt генерируется группа из G completions, и преимущества (advantages) вычисляются как нормированные отклонения награды от среднего по группе:

A_i = (r_i − mean(r)) / std(r)

Это позволяет значительно сократить вычислительные затраты и устранить необходимость обучать вторую модель-critic. Группы обычно содержат G = 8--16 completions, что даёт достаточную статистику для оценки относительного качества.

GRPO имеет несколько важных модификаций. Dr. GRPO \[7\] предлагает использовать константную нормировку длины (constant length normalization) вместо стандартной, что устраняет смещение в пользу более коротких completions. GSPO (Group Sequence Policy Optimization) \[2\], развиваемое командой Qwen, переносит importance sampling на уровень последовательности (а не токена), что даёт более стабильный сигнал при обучении длинных генераций.

Ключевая проблема GRPO-обучения --- разреженность наград. Если все G completions в группе получают одинаковую нулевую награду, то std(r) = 0, все advantages = 0, и градиент также нулевой. Это приводит к застою обучения.

## 1.3. Проблема неограниченной генерации при RL-обучении thinking-моделей

При применении GRPO к моделям с thinking mode возникает специфическая проблема, не наблюдаемая для non-thinking моделей. Во время rollout-генерации модель входит в неограниченный цикл рассуждений и не генерирует закрывающий токен \`\</think\>\` в пределах установленного лимита max_completion_length.

Причина лежит в специфике обучения thinking-моделей: они обучались генерировать \`\</think\>\` как «естественный» сигнал завершения рассуждения, основанный на внутренней уверенности в найденном решении. При RL-обучении на сложных задачах уверенность не достигается в пределах бюджета токенов, и модель продолжает рассуждать бесконечно, пока не сработает жёсткое ограничение по длине.

Последствия для GRPO критичны: 100 % completions обрезаются без формулировки ответа и получают нулевую награду. Обратная связь для обучения отсутствует, и алгоритм не может продвигаться. Данная проблема документирована в open-source проектах (vLLM issue #15418, TRL issue #2801, open-r1), но общее решение в открытом доступе отсутствовало на момент начала исследования.[]{#_Toc227571901 .anchor}

## 1.4. Современные методы alignment: KTO и DPO

После RL-стадии (GRPO/GSPO) для полировки модели применяются методы на основе предпочтений --- Kahneman-Tversky Optimization (KTO) \[9\] и Direct Preference Optimization (DPO) \[10\].

DPO устанавливает прямую связь между парами предпочтений (выбранный ответ y⁺ и отвергнутый ответ y⁻) и градиентом обновления политики, минуя этап обучения reward-модели. Функция потерь DPO имеет вид:

L_DPO = −log σ(β·(log π(y⁺\|x)/π_ref(y⁺\|x) − log π(y⁻\|x)/π_ref(y⁻\|x)))

KTO предлагает альтернативный подход, основанный на проспективной теории Канемана-Тверски: вместо пар (y⁺, y⁻) используются отдельные примеры с бинарной меткой (desirable / undesirable). Функция потерь KTO использует ассимметричную функцию ценности с точкой отсчёта, что лучше соответствует эмпирически наблюдаемому человеческому принятию решений.

В контексте сократического STEM-тьютора KTO особенно эффективна для alignment по стилю объяснения: мы можем собрать большое количество примеров «сократических» ответов (с наводящими вопросами) и «прямых» ответов (с выдачей готового решения), без необходимости строить явные пары.

# 2. МЕТОДОЛОГИЯ ИССЛЕДОВАНИЯ

## 2.1. Формализация задачи и архитектура решения

Задача исследования формализуется следующим образом. Дана базовая thinking-модель M₀ (Qwen3.5-9B с enable_thinking support) и обучающий набор STEM-задач D = {(x_i, y_i\*)}\_i=1\^N с верифицируемыми правильными ответами y_i\*. Требуется построить дообученную модель M\*, максимизирующую ожидаемую награду:

M\* = argmax E\_{(x,y\*) ∼ D} \[r(M(x), y\*)\]

где r --- верифицируемая функция награды (SymPy-проверка для математики, ChemPy для химии, regex для физики, exact match для информатики и биологии). Дополнительное ограничение --- Сохранение сократического стиля объяснений, измеряемое отдельным качественным показателем Socratic score \[0, 1\].

Предлагаемая архитектура решения состоит из трёх взаимодополняющих компонентов, каждый из которых решает конкретный барьер сходимости RL-обучения:

- ThinkingBudgetProcessor --- устраняет проблему неограниченной генерации thinking-блоков через контролируемое завершение.

- Cold-Start SFT --- обеспечивает ненулевую базовую точность перед RL-обучением через короткое supervised дообучение.

- ReDit-дитеринг наград --- преодолевает проблему нулевой дисперсии преимуществ через гауссов шум на бинарных наградах.

Эти три компонента применяются на Стадии 1 (GSPO). Далее, для полировки модели по стилю ответов используется последовательность KTO (Стадия 2) и DPO (Стадия 3).

## 2.2. Компонент 1: ThinkingBudgetProcessor

ThinkingBudgetProcessor --- процессор логитов, реализуемый как подкласс \`transformers.LogitsProcessor\`. Он интегрируется в процесс генерации токенов через \`generation_config.logits_processor\` и применяется к каждому токену в батче после вычисления логитов, но до операции softmax для выбора следующего токена.

Процессор ведёт счёт токенов рассуждения для каждой последовательности в батче. При достижении заданной доли бюджета (SOFT_RATIO = 0,90, что для THINKING_BUDGET = 1500 соответствует 1350 токенам) процессор усиливает логит токена \`\</think\>\` на константу +5,0, создавая «soft nudge» --- мягкое подталкивание модели к завершению рассуждения.

При полном исчерпании бюджета (1500 токенов) процессор устанавливает все логиты, кроме токена \`\</think\>\`, в −∞, принудительно заставляя модель сгенерировать закрывающий токен на следующем шаге (hard force). После завершения thinking-фазы процессор переключается в пассивный режим и не влияет на дальнейшую генерацию ответа.

Двухступенчатый подход «soft nudge + hard force» важен по двум причинам. Во-первых, soft nudge в зоне 1350--1500 токенов позволяет модели естественно завершить рассуждение вблизи границы бюджета, сохраняя качество решения. Во-вторых, hard force на 1500 токенов обеспечивает жёсткую гарантию завершения даже в случаях, когда модель «упорно» продолжает рассуждать.

Важная техническая деталь реализации --- корректная работа в батче. Процессор хранит отдельный счётчик токенов рассуждения для каждой последовательности в батче, и применяет соответствующий режим (soft / hard / off) индивидуально. Это критично для GRPO, где G completions генерируются параллельно в одном батче.[]{#_Toc227571905 .anchor}

## 2.3. Компонент 2: Cold-Start SFT

Cold-Start SFT --- стратегия «холодного старта», вдохновлённая подходом DeepSeek-R1 \[1\]. Перед началом основного RL-обучения модель проходит короткий этап supervised fine-tuning (SFT) на корректных решениях, полученных методом rejection sampling из самой базовой модели.

Процедура Cold-Start SFT включает четыре этапа. На первом этапе из обучающего корпуса отбирается подмножество из 500 задач лёгкого уровня сложности (GSM-8K, начальные уровни физики и химии). На втором этапе для каждой задачи генерируется решение базовой моделью с применением ThinkingBudgetProcessor. На третьем этапе сгенерированные решения автоматически верифицируются: SymPy для математических выражений (с символьным упрощением), ChemPy для химических реакций и стехиометрических расчётов, regex-сопоставление с допуском для физических величин. На четвёртом этапе модель дообучается на отфильтрованных корректных решениях в течение 200 шагов SFT с малым learning rate.

Типичный выход Cold-Start SFT --- дообученная модель с базовой точностью 15--30 % на валидационном наборе (против \~5 % для «сырой» базовой модели). Это повышение базовой точности критично для GRPO: наличие ненулевой доли корректных completions в группах обеспечивает ненулевую дисперсию преимуществ и, следовательно, ненулевой градиентный сигнал.[]{#_Toc227571906 .anchor}

## 2.4. Компонент 3: ReDit-дитеринг наград

ReDit (Reward Dithering) \[6\] --- метод добавления небольшого гауссова шума к бинарным наградам за корректность. Для каждого completion с наградой r ∈ {0, 1} итоговая награда определяется как:

r\' = r + ε, где ε ∼ N(0, σ²), σ = 0,05

Малое значение σ = 0,05 обеспечивает, что шум не существенно влияет на ранжирование корректных и некорректных completions (гарантированно r\'(correct) \> r\'(incorrect) в 99 % случаев), но при этом создаёт непрерывный ландшафт наград с ненулевой дисперсией даже в группах, где все completions одинаково ошибочны.

Философская мотивация ReDit противоположна zero-variance masking --- подходу, при котором группы с нулевой дисперсией вообще исключаются из обучения. Маскирование теряет обучающий сигнал из сложных задач, где все completions некорректны. ReDit, напротив, сохраняет слабый, но ненулевой сигнал, который со временем может направить обучение в сторону постепенного улучшения сложных случаев. Согласно \[6\], ReDit даёт более высокую итоговую точность на hard-задачах по сравнению с masking-стратегией.[]{#_Toc227571907 .anchor}

## 2.5. Трёхстадийный пайплайн обучения: GSPO → KTO → DPO

Обучение проводится в три последовательные стадии, каждая из которых решает свою задачу оптимизации модели.

Стадия 1 (GSPO) --- RL-обучение с верифицируемыми наградами. Применяется curriculum learning (постепенное увеличение сложности задач от GSM-8K до MATH и ruMMLU STEM), Dr. GRPO constant length normalization \[7\], а также GDPO decoupled reward normalization \[8\] с тремя сигналами награды: корректность (вес 0,7), формат (0,15) и сократический стиль (0,15). GSPO использует importance sampling на уровне последовательности \[2\], что обеспечивает более стабильный сигнал обучения.

Стадия 2 (KTO) --- Kahneman-Tversky Optimization \[9\] для alignment по сократическому стилю объяснений. Собирается датасет из 12 597 примеров с бинарными метками: «сократический ответ» (желателен) и «прямой ответ» (нежелателен). KTO обучает модель предпочитать сократический стиль без необходимости явных пар предпочтений.

Стадия 3 (DPO) --- Direct Preference Optimization \[10\] для финальной полировки формата и стиля ответов. Собирается датасет из 3 875 пар сократических диалогов, где модель обучается предпочитать более качественный вариант объяснения.[]{#_Toc227571908 .anchor}

## 2.6. Сбор и подготовка обучающих данных

Для обучения использованы три основных источника данных:

- MGSM Russian (250 задач) --- перевод на русский GSM-8K математических задач для школьного уровня.

- ruMMLU STEM (3 210 задач) --- русскоязычный срез MMLU, сфокусированный на STEM-дисциплинах (физика, химия, биология, информатика).

- Авторский набор (218 задач) --- задачи, отобранные и адаптированные для русскоязычных школьников 7--11 классов, с акцентом на сократический стиль объяснения.

Общий объём данных для GSPO-стадии --- 3 678 задач, из которых 500 выделены для Cold-Start SFT. Верификация ответов автоматизирована, что позволяет использовать их как «ground truth» в RL-награде без ручной разметки.

Для KTO-стадии собран отдельный датасет из 12 597 сократических/прямых ответов. Для DPO --- 3 875 пар предпочтений. Все данные находятся в репозитории в JSONL-формате.

Обучение проводилось на GPU NVIDIA RTX PRO 6000 (102 ГБ VRAM) в среде Google Colab. Гиперпараметры GSPO-стадии оптимизированы на основе литературного анализа:

- LoRA r = 16, alpha = 32 --- оптимально для RL согласно Tina \[11\]: r = 16 даёт 48,92 % против r = 32 --- 48,47 % и r = 64 --- 46,95 %.

- Learning rate = 5 × 10⁻⁷ --- консервативный выбор при разреженной награде.

- G = 8 completions на prompt, MAX_COMPLETION = 2048 токенов, THINKING_BUDGET = 1500 токенов.

- Loss type --- dr_grpo \[7\], importance_sampling_level = sequence (GSPO) \[2\].

- Оптимизатор --- AdamW (Стадия 1), Lion 8-bit (Стадия 2)

## 3.3. Сравнение подходов к проблеме thinking-сходимости

### Методика оценки и описание метрик

Сравнительная оценка четырёх конфигураций управления длиной цепочки рассуждения на стадии GSPO проведена по трём метрикам, характеризующим стабильность обучения и достижение целевого поведения модели. Результаты измерений приведены в таблице 3.2 и проиллюстрированы на рисунке 3.2. Формальные определения метрик приведены ниже.

Clipped ratio (доля отсечённых траекторий). Доля обучающих эпизодов, в которых длина генерации достигла лимита max_tokens без появления закрывающего тега \</think\>. Формально: clipped_ratio = N_clipped / N_total, где N_clipped --- число эпизодов, завершённых принудительно. Высокое значение (100 %) индикатор того, что модель не укладывается в бюджет и все rollout\'ы считаются неинформативными для policy gradient. Целевое значение \< 20 % обеспечивает статистическую значимость обновлений политики.

Correctness reward (шаг 50). Средняя правильность ответа модели, измеренная как доля совпадений с эталонным ответом по бинарной метрике reward ∈ {0, 1} на 50-м шаге обучения GSPO. Выбор шага 50 обусловлен тем, что к этому моменту эффекты warmup и Cold-Start SFT стабилизируются. Значение 21,7 % соответствует начальной фазе улучшения над базой и свидетельствует об успешном преодолении стартовой деградации.

Сходимость (convergence). Бинарный показатель: обучение считается сошедшимся, если correctness reward на последних 10 шагах монотонно неубывает с общим приростом не менее 5 п.п. относительно шага 0. В противном случае фиксируется отсутствие сходимости. Для подходов 1--3 (без ThinkingBudgetProcessor) reward колеблется вокруг нуля из-за 100 % clipped ratio --- обучение не начинается. Подход 4 демонстрирует монотонный рост, что свидетельствует о корректной работе предложенного метода.

  Биология       28,6        37,2        40,5        43,0              +14,4

  Среднее        55,1        63,5        64,8        66,5              +11,4
  --------------------------------------------------------------------------------

Как видно из таблицы 3, наибольший прирост точности обеспечивает стадия GSPO (+8,4 процентных пункта по macro-average), что подтверждает эффективность обучения с подкреплением на верифицируемых наградах. Стадии KTO (+1,3 п.п.) и DPO (+1,7 п.п.) обеспечивают дополнительный прирост, преимущественно за счёт улучшения формата ответов и сократического стиля объяснений.

Наибольший относительный прирост наблюдается в доменах с низкой базовой точностью: биология (+14,4 п.п., с 28,6 % до 43,0 %) и информатика (+12,1 п.п., с 46,5 % до 58,6 %). Это объясняется тем, что curriculum learning с повышенным весом для сложных задач (hard = 1,5×) направляет обучение именно на слабые домены. Математика, где базовая точность уже высока (79,1 %), показывает более умеренный прирост (+9,1 п.п.), что свидетельствует об отсутствии деградации в сильных доменах --- сохраняется эффект «поднять слабые, не уронить сильные».

# ЗАКЛЮЧЕНИЕ

В результате проведённой научно-исследовательской работы предложен и апробирован метод управляемого рассуждения для RL-дообучения языковых моделей с thinking mode. Систематический анализ четырёх итераций экспериментов выявил корневую причину несходимости GRPO-обучения thinking-моделей --- отсутствие механизма принудительного завершения фазы рассуждения в TRL-генерации.

Основные научные и практические результаты работы:

1.  Предложен компонент ThinkingBudgetProcessor --- процессор логитов с двухступенчатым механизмом «soft nudge + hard force», обеспечивающий гарантированное завершение фазы рассуждения в пределах заданного бюджета токенов.

2.  Разработана стратегия Cold-Start SFT с применением rejection sampling из базовой модели для обеспечения ненулевой начальной точности (15--30 %) перед RL-обучением.

3.  Интегрирован ReDit-дитеринг наград (Gaussian σ = 0,05) для преодоления проблемы нулевой дисперсии преимуществ при разреженной бинарной награде.

4.  Построен трёхстадийный пайплайн обучения GSPO → KTO → DPO, обеспечивающий последовательное улучшение точности (GSPO +8,4 п.п.) и сократического стиля (KTO +0,27 по Socratic score).

5.  Получена специализированная STEM-модель на базе Qwen3.5-9B, превосходящая базовую версию на 11,4 п.п. по macro-average (с 55,1 % до 66,5 %) на бенчмарке из 3 678 задач, с наибольшим приростом в биологии (+14,4 п.п.) и информатике (+12,1 п.п.).

Комбинация ThinkingBudgetProcessor + Cold-Start SFT + ReDit-дитеринг формирует целостную методологию, устраняющую три ключевых барьера сходимости GSPO-обучения thinking-моделей. Предложенный пайплайн применим не только к задаче STEM-тьюторства, но и к любой задаче домен-специфичного дообучения thinking-LLM с верифицируемыми наградами.

Практическое применение полученной модели планируется в интеллектуальной тьюторской системе MITS для русскоязычных учеников 7--11 классов, находящейся в разработке. Модель интегрирована в пайплайн многоагентного тьютора (Profiler → Planner → Tutor → Verifier), где занимает позицию Tutor-агента.

Направления дальнейших исследований: (1) исследование применимости методологии к моделям других семейств (DeepSeek-R1, QwQ, Mistral-R); (2) разработка адаптивного THINKING_BUDGET --- динамически изменяемого в зависимости от сложности задачи; (3) совмещение управляемого рассуждения с MoE-архитектурами для дальнейшего сокращения вычислительных затрат.

# ПРИЛОЖЕНИЕ А --- Реализация ThinkingBudgetProcessor

Ниже приведён полный псевдокод компонента ThinkingBudgetProcessor на языке Python, реализующий двухступенчатый механизм «soft nudge + hard force» для управляемого завершения thinking-фазы.

> from transformers import LogitsProcessor\
> import torch\
> \
> class ThinkingBudgetProcessor(LogitsProcessor):\
> \"\"\"Контролирует бюджет thinking-токенов в каждой\
> последовательности батча.\"\"\"\
> \
> def \_\_init\_\_(self, tokenizer, thinking_budget=1500, soft_ratio=0.9,\
> soft_bias=5.0):\
> self.think_open_id = tokenizer.convert_tokens_to_ids(\'\<think\>\')\
> self.think_close_id = tokenizer.convert_tokens_to_ids(\'\</think\>\')\
> self.budget = thinking_budget\
> self.soft_threshold = int(thinking_budget \* soft_ratio)\
> self.soft_bias = soft_bias\
> \# Per-sequence state (batched generation)\
> self.in_thinking = {} \# idx -\> bool\
> self.thinking_tokens = {} \# idx -\> count\
> \
> def \_\_call\_\_(self, input_ids: torch.LongTensor,\
> scores: torch.FloatTensor) -\> torch.FloatTensor:\
> batch_size = input_ids.shape\[0\]\
> for idx in range(batch_size):\
> last_token = input_ids\[idx, -1\].item()\
> \# Detect thinking-phase start\
> if last_token == self.think_open_id:\
> self.in_thinking\[idx\] = True\
> self.thinking_tokens\[idx\] = 0\
> elif last_token == self.think_close_id:\
> self.in_thinking\[idx\] = False\
> \
> if not self.in_thinking.get(idx, False):\
> continue \# pass-through outside thinking\
> \
> self.thinking_tokens\[idx\] += 1\
> used = self.thinking_tokens\[idx\]\
> \
> if used \>= self.budget:\
> \# HARD FORCE: only \</think\> token is permitted\
> scores\[idx, :\] = float(\'-inf\')\
> scores\[idx, self.think_close_id\] = 0.0\
> elif used \>= self.soft_threshold:\
> \# SOFT NUDGE: boost \</think\> logit\
> scores\[idx, self.think_close_id\] += self.soft_bias\
> return scores

Применение процессора в конфигурации генерации:

> from transformers import GenerationConfig, LogitsProcessorList\
> \
> processor = ThinkingBudgetProcessor(\
> tokenizer=tokenizer,\
> thinking_budget=1500,\
> soft_ratio=0.9,\
> soft_bias=5.0,\
> )\
> generation_config = GenerationConfig(\
> max_new_tokens=2048,\
> temperature=0.7,\
> top_p=0.9,\
> logits_processor=LogitsProcessorList(\[processor\]),\
> )\
> output = model.generate(input_ids, generation_config=generation_config)
