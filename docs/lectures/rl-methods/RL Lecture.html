// 02 · MOTIVATION04 / 20
Проблема

Почему SFT недостаточно

SFT максимизирует правдоподобие демонстраций. У этого три фундаментальных ограничения:

I

Нет ранжирования

Все «хорошие» примеры равны. Модель не знает, какое объяснение лучше другого.

II

Distribution shift

На инференсе модель попадает в собственные сэмплы. Ошибки накапливаются.

III

Сложно «отрицание»

SFT не умеет учить тому, чего не делать (например — не спойлерить).

RL добавляет сигнал предпочтения: что лучше, что проходит верификатор, как реагирует студент.

// 03 · BASE TASK05 / 20
Единая формулировка

Все методы — один лосс

maxθ Ex∼D, y∼πθ [ r(x, y) ] − β · KL[ πθ ‖ πref ]
r — награда: RM, верификатор или неявная
πref — референс, обычно SFT-чекпоинт
β — сила KL: держит политику рядом с референсом
π*(y|x) ∝ πref(y|x) · exp( r(x, y) / β )

мост, по которому пойдут DPO и KTO →

// 04 · PREFERENCE MODEL06 / 20
Источник сигнала

Bradley–Terry · модель выбора

На один вход x аннотатор выбирает между yw (winner) и yl (loser).

P( yw ≻ yl | x ) = σ( r*(x, yw) − r*(x, yl) )
LRM = − log σ( rφ(x, yw) − rφ(x, yl) )
КЛАССИКА
пары → RM → PPO с rφ
DPO-ТРЮК
пары → политика напрямую (rφ сократится)

// 07 · DPO09 / 20
Rafailov · NeurIPS 2023

DPO · напрямую к политике

Вывод
r*(x, y) = β · log( π*(y|x) / πref(y|x) ) + c(x)
↓ подставляем в Bradley–Terry
LDPO = − E[ log σ( β · ( logw−logl ) ) ]
где log· = log[πθ(y·|x)/πref(y·|x)]
Магия
  • ✦ никакой RM
  • ✦ никакого RL-цикла
  • ✦ никакого critic
  • ✦ supervised-style лосс
  • ✦ только пары + 2 модели в памяти
⚠ слабости
length bias · шум разметки · off-policy gap

// 08 · KTO10 / 20
Ethayarajh · 2024 · prospect theory

KTO · когда пар нет

В проде сигнал бинарный: лайк/дизлайк, «понял/не понял», «решил/не решил». Канеман–Тверски: потери ≠ выигрыши по силе.

rθ(x,y) = β · log( πθ(y|x) / πref(y|x) )
vθ = λD·σ(rθ−zref) если desirable
vθ = λU·σ(zref−rθ) если undesirable
LKTO = E[ 1 − vθ(x, y) ]
Сигналы в MITS
+ лайк под объяснением
+ решение задачи после подсказки
− переспрос «не понял» < 30s
− закрытие сессии без решения
λU > λD — «плохое» болезненнее «хорошего». KTO хорошо живёт с дисбалансом 5:1.

// 09 · GSPO11 / 20
Qwen team · 2025

GSPO · последовательность целиком

На длинных reasoning-трейсах токеновый ratio накапливает дисперсию. Clip срабатывает не там, где надо. Решение: один ratio на всю последовательность.

si(θ) = ( πθ(oi|q) / πθold(oi|q) )1/|oi|
LGSPO = (1/G)·Σi min( si·Âi, clip(si, 1±ε)·Âi )

меньше шум · корректные градиенты на длинных trace · мягче для MoE

// 11 · LIGHT ALTERNATIVES13 / 20
PPO без лишнего

DAPO · RLOO · ReMax

Насколько ещё можно упростить on-policy RL?

★ DAPO · ByteDance 2025

Decoupled clip + dynamic sampling

Asymmetric ε для +/− advantages · dynamic sampling (отбрасываем «плоские» группы) · token-level loss · overlong filtering. SOTA AIME 2024 на Qwen2.5-32B.

REINFORCE++

Вильямс 1992++

Per-token KL, нормирование, PPO-clip. Без critic. Простейший baseline.

RLOO

Leave-One-Out

Baseline = среднее остальных k−1. Несмещённо, низкая дисперсия. ≈ PPO дешевле.

ReMax

Argmax baseline

Baseline = greedy generation. 1 лишний forward вместо value-сети. ~2× быстрее PPO.

// 12 · DPO FAMILY14 / 20
4 слабости → 4 решения

Семейство DPO

★ IPO · Azar 2024

Identity preference

Квадратичный лосс вместо log-σ. Не уходит в ∞ при детерминированных предпочтениях.

LIPO = ( Δw − Δl − 1/(2β) )²
★ SimPO · Meng 2024

Simple — без πref

Length-normalized log-likelihood + явный margin γ. 1 модель в памяти, нет length bias.

L = − log σ( β·(sw/|yw| − sl/|yl|) − γ )
★ CPO · Xu 2024

Contrastive + SFT

LCPO = LDPO + λ·NLL(yw|x). Качество генерации (MT, code).

★ ORPO · Hong 2024

Odds-ratio · 1 модель

SFT + preference в одном проходе. Без πref, без отдельной SFT-стадии. Стартует с base.

// 16 · DECISION MAP18 / 20
Что выбрать?

Карта решений

if verifier (SymPy, тесты, formatter):
↳ длинные reasoning → GSPO
↳ короткие ответы → GRPO / DAPO
elif пары (human ranking, LLM-judge):
↳ чистые → DPO
↳ шумные / мало → KTO / IPO
↳ из base без SFT → ORPO
elif бинарь (лайки, completion):
↳ KTO
elif unlearning:
↳ NPO
else: # много железа, всё есть
PPO или каскад GSPO → KTO → DPO

// 17 · PITFALLS19 / 20
Подводные камни

Failure modes

⚠ REWARD HACKING

Дешёвый путь к награде

Длинные псевдо-выкладки набирают format-score без correctness. Лечить: ограничить длину, штраф за повторы, composite reward, LLM-judge.

⚠ KL-COLLAPSE

β слишком мал/велик

Политика уезжает от ref → теряет язык. Или ничего не учится. DPO/KTO: β = 0.05–0.2; мониторить KL онлайн.

⚠ LENGTH BIAS

Длинные ≈ выигрывают

Σ logprob больше у длинного ответа. Лечить: length-normalized DPO, R-DPO, SimPO, штраф в reward.

⚠ OFF-POLICY GAP

πref устаревает

Данные собирались давно — «неявная награда» становится неточной. Лечить: Iterative DPO, ORPO, Self-Rewarding LM.
